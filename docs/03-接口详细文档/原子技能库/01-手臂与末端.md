## `multi_timed_command`

**用途**：可配置的多 planner 单次组合控制（如 2/8/9、3/6/7） **源码**：`skills/atomic/refactored_sdk/multi_timed_command.py`。

**主要参数**：`commands`, `desire_time`, `is_sync`, `focus_ee`, `prepare_arm_control`, `settle_time`；另有通用 `timeout`。全部字段和默认值以 `MultiTimedCommandParams` 为准。

**实际输入**：示例中的 `commands` 须从当前场景的真实输入或明确标记的仿真配置取得。

**调用片段**：

```python
from skills.atomic.refactored_sdk.multi_timed_command import MultiTimedCommandParams, MultiTimedCommandSkill
params = MultiTimedCommandParams(commands=commands, desire_time=3.0)
skill = MultiTimedCommandSkill(hw)
result = run_skill(skill, params)  # run_skill 定义在本库 README
print(result.success, result.message)
```

**运行条件**：commands 必须是非空的 planner 命令序列；空序列初始化失败。`prepare_arm_control=True`（默认）在含 planner 2–9 时，发令前调用 `set_arm_control_mode(2)` 并检查返回结果，切换失败或接口缺失则不下发。纯底盘 planner 0/1 不切换；关闭此参数时由调用方确保外部控制模式。只检查切换返回结果，不额外读取模式状态，不执行物理复位，也不在结束后切回保持模式 0。`focus_z` 跟随 `focus_ee`，焦点设置不能代替手臂控制模式准备。直接调用 Adapter 不经过这一步。

**结果判定**：初始化与每次执行均检查 Result.success；只有 is_finished() 为真才算完成。失败时保留 message 并定位上游输入或适配器。本片段为源码核对示例，仿真/真机验证待逐项记录。
