## `palletizing_line_mpc_restore`

**用途**：继承 `PalletizingLineMpcSkill`，复用原 MPC 搬运实现，并增加双臂 14 关节与下肢 4 关节的快照恢复。正常完成、失败或异常后均尝试恢复全部 18 个关节。`arms=left/right` 只限制搬运手臂，不限制快照与恢复范围。**源码**：`skills/atomic/refactored_sdk/palletizing_line_mpc_restore.py`。

**主要参数**：默认 `prepare_pose=False`；`roundtrip_axis='full'` 保持原 10 段码垛路径，设为 `x` / `y` / `z` 时改为对应单轴的“伸出 + 原路返回”两段路径。X 距离和方向使用 `x_distance` / `x_direction`，Y 使用 `y_offset` / `lateral_direction`，Z 使用 `z_height` 并沿 +Z 伸出。`restore_time=5.0`（双臂恢复秒数）、`restore_verify_delay=0.2`、`restore_arm_tolerance_deg=2.0`、`restore_leg_tolerance=2.0`。其余搬运字段与 `PalletizingLineMpcParams` 一致。

**恢复与结果判定**：

1. 首次执行前读取完整快照；任一组读取失败就取消搬运，不下发运动或部分恢复命令。
2. 恢复时依次请求手臂控制模式 1 和 2，再分别下发双臂、下肢快照；单组失败不阻止另一组恢复尝试。
3. 恢复后重新读取 18 个关节并计算误差。发送成功但读回超差、读回失败或任一组命令失败，技能均返回 `Result.fail`，不能把发送成功当作恢复到位。
4. 手臂读取为弧度，下发恢复轨迹前显式转角度；下肢读取经 `_from_rad` 返回用户单位。当前验收入口使用默认 `angle_unit=deg`，与 `send_leg_joint_command` 固定角度写入一致。不能改走 `send_leg_joint_sdk`，因为其 `finally` 会调用 `reset_torso_to_initial()`，覆盖下肢快照。

**验收脚本**：

```bash
python3 apps/test_kuavo_5w_skills/test_palletizing_line_mpc_restore.py --arms both
python3 apps/test_kuavo_5w_skills/test_palletizing_line_mpc_restore.py --arms left --roundtrip-axis y
```

`--roundtrip-axis` 可选 `full` / `x` / `y` / `z`，默认 `full`。入口使用 `sdk_managers_whitelist=['arm', 'timed', 'low']`。它有意不调用 `skill_setup` / `skill_teardown`，也不在 `finally` 中执行 `arm_reset` 或 `reset_torso_to_initial`，避免快照前或恢复后复位覆盖目标角度。搬运成功但恢复验证失败时，脚本仍退出 1。
