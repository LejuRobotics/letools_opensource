# 03 相机适配器测试脚本

`apps/test_camera_adapter/` 是真机上手动运行的验证脚本目录，用来确认 `CameraAdapter`（相机）和 `PerceptionAdapter`（感知）在 ROS 侧确实工作，包括话题有没有数据、TF 链是否完整、进程能否清理干净。目录下现在是 15 个脚本，没有 `__init__.py`；`pytest.ini` 的 `testpaths` 不含 `apps/`，所以这些脚本不会被 CI 自动收集（见 [`06-apps-测试与示例应用.md`](../06-apps-测试与示例应用.md) 的「与 pytest 的关系」）。

本文中的相对路径一律相对 **LeTools 仓库根目录**，命令都在仓库根目录下执行。

### test_camera_carton.py

托盘场景专用的初始化脚本，与 `test_camera_init.py` 只差一行：`DEFAULT_CONFIG` 指向 `config/camera_config_carton.yaml`（`apps/test_camera_adapter/test_camera_carton.py:26`），其余代码完全相同。它验证的仍然是 `CameraAdapter.initialize()` 返回 `Result(success=True)` 且 roslaunch 正常起来，命令行参数也与 init 版一致（`--config` / `--keep-alive` / `--rviz`，无 `--reuse`）。

两个配置文件的差别只有头部分辨率与帧率：`camera_config.yaml` 是 1280×800@15，`camera_config_carton.yaml` 是 640×480@30，其余字段逐一相同。托盘检测链上的 OBB 模型 `imgsz=640`，用 640×480 进图可以省掉 letterbox 的开销，这是 carton 配置单独存在的理由。

## 运行方式

四个开关（`--keep-alive` / `--reuse` / `--rviz` / `--config`）的含义见 [`06-apps-测试与示例应用.md`](../06-apps-测试与示例应用.md) 的「相机脚本的四个开关」一节，这里只说怎么组合。

### 方式一：重用模式（`--reuse`，推荐）

先启动一次相机并保持运行，之后反复跑各项测试，不必每次等 3 秒 launch：

```bash
# 终端 1：启动相机并常驻（默认读 config/camera_config.yaml）
python3 apps/test_camera_adapter/test_camera_init.py --keep-alive

# 托盘配置启动
python3 apps/test_camera_adapter/test_camera_carton.py --keep-alive

# 换一份配置
python3 apps/test_camera_adapter/test_camera_init.py --config config/camera_config_carton.yaml --keep-alive

# 同时打开 rviz（biped_s4_head.rviz）
python3 apps/test_camera_adapter/test_camera_init.py --keep-alive --rviz

# 终端 2：逐个跑 --reuse 测试（秒级，跳过 launch/TF/rviz）
python3 apps/test_camera_adapter/test_camera_frame.py --reuse
python3 apps/test_camera_adapter/test_camera_depth.py --reuse
python3 apps/test_camera_adapter/test_camera_pointcloud.py --reuse
python3 apps/test_camera_adapter/test_camera_status.py --reuse
python3 apps/test_camera_adapter/test_camera_tf.py --reuse

# PerceptionAdapter（仅 camera 数据委托部分）
python3 apps/test_camera_adapter/test_perception_frame.py --reuse
```

Jetson 上的适配器进程会在导入 NumPy/OpenCV/CvBridge 之前，把 OpenBLAS、OpenMP 和 OpenCV 的线程数默认限制为 1，避免启动瞬间占满全部 CPU 核。需要提高数值计算并行度时，在启动前覆盖统一配置：

```bash
LETOOLS_NUMERIC_THREADS=2 \
python3 apps/test_camera_adapter/test_camera_init.py --keep-alive
```

也可以单独设置 `OPENBLAS_NUM_THREADS`、`OMP_NUM_THREADS`、`OPENCV_FOR_THREADS_NUM` 或 `LETOOLS_OPENCV_THREADS`；显式设置的库级配置优先于 `LETOOLS_NUMERIC_THREADS`。

`test_camera_init.py` 和 `test_camera_shutdown.py` 不接受 `--reuse`，它们测的就是初始化和清理本身。`test_camera_rviz.py` 接受该参数，但复用时跳过了 launch，也就测不到 rviz 开关行为，真机上建议直接用 `test_camera_init.py --rviz` 验证。

rviz 的看点在机器人显示器上：RGB、深度、点云三路话题应当有实时画面。只想快速确认 rviz 能弹出来，可以跑 `python3 apps/test_camera_adapter/test_camera_init.py --rviz`，3 秒后自动退出。

### 方式二：独立运行

以下脚本内部会自己初始化 `CameraAdapter`。跑之前**必须先 Ctrl+C 停掉 `--keep-alive` 的进程**，否则两套 roslaunch 会冲突：

```bash
# CameraAdapter 资源清理（3s init → shutdown，约 5 秒）
python3 apps/test_camera_adapter/test_camera_shutdown.py

# PerceptionAdapter 初始化与依赖注入
python3 apps/test_camera_adapter/test_perception_init.py

# PerceptionAdapter 资源清理（init → start → shutdown）
python3 apps/test_camera_adapter/test_perception_shutdown.py

# AprilTag 检测（需要二维码对准相机视野）
python3 apps/test_camera_adapter/test_perception_apriltag.py

# 端到端验证
python3 apps/test_camera_adapter/e2e_camera_perception.py

# 感知适配器综合测试
python3 apps/test_camera_adapter/test_perception_adapter.py
```

推荐顺序：先用方式一把 CameraAdapter 的功能全部过一遍，停掉常驻进程，再用方式二逐个跑 PerceptionAdapter 与 shutdown 相关脚本。

### 方式三：pytest 单元测试（无需相机与 ROS master）

`adapters/hardware/leju_wheeled/tests/test_camera_adapter_sync.py` 用 mock 覆盖 RGBD 同步逻辑，不需要真机：

```bash
python3 -m pytest adapters/hardware/leju_wheeled/tests/test_camera_adapter_sync.py -v
```

它验证的是配对的几个边界：正常配对写入缓存、`message_filters` 近似同步能调到回调、超出 slop 的配对被拒、零时间戳被拒、宽高不一致被拒。

### 底层参数修改指引

以下参数不在 `camera_config.yaml` 中暴露，要改就编辑对应文件：

| 参数 | 位置 | 说明 |
|------|------|------|
| RGB/深度分辨率、帧率 | `config/camera_config.yaml`（`color_width/height/fps`、`depth_width/height/fps`）→ 经 `config/camera_orbbec.launch` 传入 `gemini_330_series.launch` | 改 yaml 即可，不必动 launch 文件 |
| 二维码家族、检测参数、标签尺寸与 ID 列表 | `config/apriltag_config.yaml`（`tag_family`、`tag_threads`、`tag_decimate`、`standalone_tags` 等；由 `config/apriltag_config.yaml.template` 复制） | 由 `config/apriltag_continuous.launch` 作为 `config_file` 加载 |

设计原则：适配器层只管自己的行为（启动哪个 launch、要不要 TF/rviz/AprilTag），驱动与算法的参数留给各自的配置文件，`infrastructure/ros_packages/` 里的原始文件保持零修改。

## API 参考

`CameraAdapter` 与 `PerceptionAdapter` 的逐方法完整签名另见 [`02-相机与底盘接口.md`](./02-相机与底盘接口.md)，本节只列测试脚本会用到的部分。

### CameraAdapter

#### 生命周期

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `initialize` | `(config: Dict[str, Any]) -> Result` | `Result(success=True/False, message=...)` | 启动相机 launch、TF 节点，订阅话题，可选启动 rviz |
| `shutdown` | `() -> Result` | `Result(success=True/False, message=...)` | 终止所有子进程（terminate → wait → kill，两轮重试），清理订阅者与缓存 |
| `is_connected` | `() -> bool` | `True` / `False` | 适配器是否已成功初始化 |

#### 数据获取

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `get_camera_frame` | `(camera_name="camera") -> Optional[CameraFrame]` | `CameraFrame` 或 `None` | 最新 RGB + 深度帧 |
| `get_synchronized_camera_frame` | `(camera_name="camera") -> Optional[CameraFrame]` | `CameraFrame` 或 `None` | 最近一组按原始 Header 时间戳配对的 RGBD |
| `wait_for_next_synchronized_camera_frame` | `(camera_name="camera", timeout_sec=2.0) -> Result` | `Result(data=CameraFrame)` | 等待调用之后产生的下一组同步 RGBD，超时返回失败 |
| `get_depth_data` | `(camera_name="camera") -> Optional[DepthData]` | `DepthData` 或 `None` | 深度图 + 内参（scale=0.001，毫米转米） |
| `get_point_cloud` | `(camera_name="camera") -> Optional[PointCloudData]` | `PointCloudData` 或 `None` | 点云数据 |
| `get_camera_info` | `(camera_name="camera") -> Optional[CameraInfo]` | `CameraInfo` 或 `None` | RGB 流的内参、分辨率、帧率 |
| `get_depth_camera_info` | `(camera_name="camera") -> Optional[CameraInfo]` | `CameraInfo` 或 `None` | 当前订阅深度流的内参 |
| `get_camera_status` | `(camera_name="camera") -> Optional[CameraStatus]` | `CameraStatus` 或 `None` | 运行状态（is_running / frame_count / fps） |

| 方法 | 签名 | 返回值 | 说明 |

| `stop_camera` | `(camera_name="camera") -> bool` | `True` | 标记相机为停止 |

### PerceptionAdapter

#### 生命周期

| 方法 | 签名 | 返回值 | 说明 |

## 使用示例

### CameraAdapter 基本用法

```python
from adapters.hardware.leju_wheeled.camera_adapter import CameraAdapter

adapter = CameraAdapter()

result = adapter.initialize({
    "enable_head": True,
    "enable_wrist_camera": False,
    "rviz": False,
})

if not result.success:
    print(f"初始化失败: {result.message}")
    exit(1)

frame = adapter.get_camera_frame("camera")
if frame:
    print(f"RGB 图像: {frame.color_image.shape}")

health = adapter.check_health("camera")
print(f"相机健康: {health['healthy']}, 帧数: {health['frame_count']}")

adapter.shutdown()
```

### PerceptionAdapter 基本用法

```python
from adapters.hardware.leju_wheeled.camera_adapter import CameraAdapter
from adapters.hardware.leju_wheeled.perception_adapter import PerceptionAdapter

camera = CameraAdapter()
camera.initialize({"enable_head": True})

perception = PerceptionAdapter()
perception.initialize(camera=camera, config={"launch_apriltag": True})

# 显式开启检测，读取不再启动进程；完成检测阶段后停止
result = perception.start()
if not result.success:
    raise RuntimeError(result.message)
try:
    tags = perception.get_tag_detections()
    for tag in tags:
        print(f"Tag {tag.tag_id}: ({tag.pose_in_world.x:.2f}, {tag.pose_in_world.y:.2f}, {tag.pose_in_world.z:.2f})")
finally:
    perception.stop()

# 也可以经由 perception 委托拿相机数据
frame = perception.get_camera_frame("camera")

perception.shutdown()
camera.shutdown()
```

### 通过 LifecycleMixin 自动初始化

在完整硬件链路里不需要手动初始化相机，`LejuWheeledArmHardware` 的 `LifecycleMixin` 会按顺序处理：

```python
# 1. rospy.init_node('leju_wheeled_arm_hardware')
# 2. 读取 config/camera_config.yaml
# 3. camera.initialize(cam_cfg)              ← CameraAdapter
# 4. perception.initialize(camera, config)   ← PerceptionAdapter（launch_apriltag=true 时）

hardware = LejuWheeledArmHardware()
hardware.initialize()

frame = hardware.camera.get_camera_frame()
result = hardware.perception.start()
if not result.success:
    raise RuntimeError(result.message)
try:
    tags = hardware.perception.get_tag_detections()
finally:
    hardware.perception.stop()
```

## 架构说明

- **CameraAdapter**：通过 `config/camera_orbbec.launch` 启动相机 ROS 节点（内部 `include` Orbbec 的 `gemini_330_series.launch`），订阅原始图像/深度/点云话题，拉起两个 TF 静态变换，可选启动 rviz。分辨率、帧率等参数从 `camera_config.yaml` 读出后传给 launch。
- **PerceptionAdapter**：通过依赖注入拿到 `CameraAdapter`，自己专注算法检测。AprilTag 由 `config/apriltag_continuous.launch` 作为 `config_file` 加载 `config/apriltag_config.yaml` 启动（该文件由 `config/apriltag_config.yaml.template` 复制，检测器参数与 `standalone_tags` 都在其中），由显式 `start()` 触发，`stop()` 停止检测但保留相机；`ar_control_node.py` 负责把 tag 位姿变换到 `base_link`。
- **ROS 节点初始化**：`rospy.init_node` 由 `LifecycleMixin` 统一负责，先于 camera/perception 初始化执行，两个适配器都不自行 `init_node`。独立跑测试脚本时要自己补这一步，见附录 A2。
- **启动顺序**（AprilTag 链路）：先订阅 `/robot_tag_info`，再启动 `config/apriltag_continuous.launch` 和 `ar_control_node.py`；最多等待 5 秒收到首条检测消息，不要求检测到 Tag。

## 附录：常见坑点

### A1. subprocess.Popen 管道阻塞

`stdout=subprocess.PIPE` / `stderr=subprocess.PIPE` 会开辟约 64KB 的内核管道缓冲区。roslaunch 输出量大，缓冲区填满后进程阻塞，相机驱动起不来。

解决：用 `stdout=subprocess.DEVNULL` / `stderr=subprocess.DEVNULL`。

### A2. --reuse 模式缺少 rospy.init_node()

`--reuse` 跳过 `CameraAdapter.initialize()` 的完整流程，改为手动调用 `_setup_subscribers()` 建 ROS subscriber。但 `rospy.Subscriber` 要求所属节点已经初始化，否则静默失效——不报错，也永远收不到消息。

完整链路里 `LifecycleMixin` 负责 `rospy.init_node()`，独立测试时 7 个 `--reuse` 脚本各自缺失，需要在 `if reuse:` 分支开头补：

```python
import rospy
if not rospy.core.is_initialized():
    rospy.init_node('test_xxx', anonymous=True)
```

### A3. Orbbec 点云话题被 remap

`gemini_330_series.launch` 末尾把点云话题从 `/camera/depth/color/points` remap 成 `/camera/depth_registered/points`。订阅者和 `rostopic echo` 都要用后一个名字。

### A4. 点云 callback 逐点循环性能

用 Python `for` 循环逐点遍历 `pc2.read_points()` 处理 92 万点（1280×720），单帧耗时远超 33ms，30Hz 下 callback 永远追不上积压。

解决：用 numpy 矢量化（`np.frombuffer()` → reshape → mask），92 万点可以压到 50ms 以内。

### A5. AprilTag TF 链路

`ar_control_node.py` 执行 `lookup_transform('base_link', source_frame, ...)` 把 tag 坐标转到机器人坐标系。完整 TF 链路：

```
base_link → ... → head_camera_base → head_camera_depth  ← 下位机 URDF
head_camera_depth → camera_link                         ← camera_adapter
camera_link → camera_color_optical_frame                ← Orbbec 驱动 publish_tf
```

缺任意一环，`/robot_tag_info` 就是空的（`ar_control_node` 会静默跳过 TF 转换失败的 tag）。

### A6. ar_control_node 的 source_frame 与相机 namespace

`ar_control_node` 默认 `source_frame=camera_color_optical_frame`。Orbbec 的 namespace 是 `/camera`，optical frame 正好是这个名字。换 RealSense（namespace `/head_camera`）时要改成 `head_camera_color_optical_frame`，`perception_adapter.py` 通过 `config.get('apriltag_source_frame', 'camera_color_optical_frame')` 支持覆盖。

### A7. 不修改 infrastructure/ 文件

按 LeTools 的架构规范，适配器自己的配置和 launch 都放在 `config/` 下，用绝对路径引用；`infrastructure/ros_packages/` 里的文件保持原样。

| 功能 | 基础设施文件 | LeTools 自有文件 |
|------|-------------|------------------|
| 相机启动 | `gemini_330_series.launch` | `config/camera_orbbec.launch` |
| 相机分辨率 | 无 | `config/camera_config.yaml` |
| AprilTag 检测 | `continuous_detection.launch` | `config/apriltag_continuous.launch` |
| AprilTag 参数与标签 | `apriltag_ros/config/settings.yaml`、`apriltag_ros/config/tags.yaml` | `config/apriltag_config.yaml` |

### A8. tag_family 和 tag_size 必须与实物一致

`tag_family` 决定二维码的编码方式（`tag16h5` / `tag36h11` 等），`size` 是黑色边框的物理边长（米）。两者任何一项与实际打印的二维码不符，检测器就完全认不出来。
