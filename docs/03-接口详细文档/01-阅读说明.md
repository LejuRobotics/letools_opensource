# 01 阅读说明

> 本章是 **路线 B（开发者）** 的接口查询手册，共 **11 篇 + 36 个 API 子节**。
> 子节编号形如 `02.01`、`03.07`、`08.04`，它们是**篇内的二级标题**，不是与篇平级的独立篇章。

## 本篇职责

统一约定接口章的阅读方式，避免各篇格式不一。读完本篇，你应该知道：

- 命名空间与模块路径怎么书写；
- 每张 API 表的列固定长什么样；
- `Result` 怎么读、怎么造；
- 异常怎么抛、在哪一层抛；
- 每一篇正文固定按什么顺序组织。

## 命名空间与模块路径

本章所有路径都写成 **`包.子包.模块.类`** 的点分形式，与 `import` 语句一致。最常用的几层是：

| 点分路径 | 实体 | 说明 |
|---|---|---|
| `core.interfaces` | `IHardware` / `ISkill` / `ICamera` / `IPerception` | 抽象接口，不依赖项目内其他层 |
| `core.domain` | `Result` / `Pose6D` / `TransformMatrix` / `SkillParams` / 各枚举 | 领域数据模型 |
| `core.common` | `exceptions` / `transform` / `interpolator` / `logger` | 通用工具 |
| `adapters.hardware.factory` | `HardwareFactory` | 硬件对象工厂（唯一推荐入口） |
| `adapters.hardware.leju_wheeled` | `LejuWheeledArmHardware` | 乐聚轮臂适配器（开发者主要调用对象） |
| `adapters.hardware.leju_wheeled.mixins` | 各 `*_mixin` | 按控制域拆开的能力模块 |
| `adapters.hardware.leju_wheeled.services.sdk_manager` | `ArmSDKManager` / `LowLevelSDKManager` / `TimedCmdManager` | SDK 管理器 |
| `skills.atomic.refactored_sdk` | 各 `<Feature>Skill` | 当前主力原子技能 |
| `skills.base.skill_base` | `SkillBase` | 所有技能的基类 |
| `orchestration.engine` | `BehaviorTreeFactory` / `BehaviorTreeController` | 行为树引擎 |
| `orchestration.nodes` | 各 `*Move` / `*Flow` 节点 | 行为树叶子节点 |
| `orchestration.utils.manifest_decorators` | `define_manifest` / `get_manifest` | 节点元数据装饰器 |

书写规则：**模块路径用反引号包住，不带 `.py` 后缀**（正文提到具体文件时才写 `xxx_move.py`）。硬件实现层在开源产物中不带 `.py`（见 `03-adapters-硬件适配层.md` 的 `03.07`）。

## 参数表格式

`02`–`06` 五篇正文中名为「类与方法详表」的 **API 契约总表**固定 5 列，表头逐字如下。技能清单、参数表和 `API参考/` 的逐方法卡片有各自的用途，不套用此表头：

| 路径 | API | 签名 | 说明 | 所属层 |
|---|---|---|---|---|
| 标准 / SDK / Timed / 查询 / 工厂 / Skill / Core | 方法名 | `方法名(参数…) -> 返回值` | 职责简述 | 实现所在的点分路径 |

其中第一列「路径」取值含义：

- **标准** —— 无后缀的标准接口，走 ROS 话题/服务，自动阻塞等待完成，跨平台、最稳；
- **SDK** —— `_sdk` 后缀，直调 Kuavo Humanoid SDK，频率高但需自行关心 MPC 模式；
- **Timed** —— `_timed` 后缀，带 `desire_time` 的时序指令，精确控时；
- **查询** —— 只读状态，不产生动作；
- **工厂** —— 创建对象；
- **Skill / Core** —— 分别指原子技能与 core 领域类型。

三条路径的选型见 `09-控制路径与选型.md`。

## `Result` 语义

`core.domain.result.Result` 是全框架统一的返回封装（`@dataclass`）。**绝大多数方法返回 `Result` 而不是抛异常。**

| 字段 | 类型 | 含义 |
|---|---|---|
| `success` | `bool` | 是否成功 |
| `message` | `str` | 结果或错误描述 |
| `data` | `Optional[Any]` | 可选返回数据（查询类常用） |
| `error_code` | `Optional[str]` | 可选错误码，便于上层针对性处理 |

两个工厂方法：

```python
from core.domain.result import Result

ok  = Result.ok("Initialized")                      # success=True, message="Initialized"
bad = Result.fail("TimedCmdManager 未初始化", error_code="TIMED_UNINITIALIZED")
```

判定写法统一为：

```python
result = hw.initialize()
if not result.success:
    logger.error(f"初始化失败: {result.message} (code={result.error_code})")
```

> 约定：**不要用 `try/except` 包住标准接口来判成败**——先看 `result.success`；只有编程错误（参数类型错、状态非法）才走异常。

## 异常族

框架根异常是 `core.common.exceptions.KuavoFrameworkError`（继承 `Exception`），四个子类分别对应四类可恢复/可诊断错误：

| 异常 | 触发场景 |
|---|---|
| `KuavoFrameworkError` | 框架基础异常（其余异常的共同父类） |
| `HardwareConnectionError` | 硬件连接失败或断开 |
| `SkillExecutionError` | 技能执行中逻辑错误或超时 |
| `ConfigurationError` | 配置文件缺失或格式错误 |
| `KinematicsError` | 运动学解算（如逆解）失败 |

### 异常 vs `Result` 的分界

| 情形 | 用哪种 |
|---|---|
| 硬件指令发送成功/失败、查询是否有值 | `Result`（`success=False`）或返回 `Optional` 的 `None` |
| 缺 `robot_type`、不支持的机器人类型 | 抛 `ConfigurationError` |
| `TransformMatrix` 传入非 4×4 矩阵 | 抛 `ValueError`（领域模型的输入校验） |

`HardwareFactory.create_hardware()` 在 `config` 缺 `robot_type` 或 `robot_type` 不受支持时直接 `raise ConfigurationError(...)`，这是异常族的典型用法。
