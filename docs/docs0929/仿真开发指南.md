# LeTools 仿真开发指南

> 适用对象：第一次部署 LeTools、ROS 和 MuJoCo 的开发者。
> 推荐系统：Ubuntu 20.04、ROS Noetic、Python 3.8+。
> 文档基线：LeTools 配套 `kuavo-ros-opensource` 1.4.5。实际使用时以 `scripts/kuavo_humanoid_sdk_tools/sdk_version.env` 为准。

[返回 LeTools README](../README.md) · [零基础教程](beginner_tutorial.md) · [常见问题](FAQ_常见问题.md)

## 1. 先理解两个项目和两个运行环境

LeTools 与 `kuavo-ros-opensource` 是两个独立项目：

```text
kuavo-ros-opensource：MuJoCo、底层控制器、ROS基础环境
LeTools：SDK适配、技能、行为树和上位机示例
```

推荐在宿主机保持同级目录：

不要把 LeTools 克隆到 `kuavo-ros-opensource` 内部。两个项目都包含 catkin 工作空间，嵌套后 catkin 可能向上找到错误的 `build`、`devel` 和 `.catkin_tools`。

本文采用以下运行方式：

```text
Docker容器：编译并运行kuavo-ros-opensource、MuJoCo和控制器
宿主机：编译并运行LeTools
通信方式：Docker使用host网络，LeTools通过ROS连接容器中的控制器
```

同一个 catkin 工作空间不要交替在宿主机和容器中编译。catkin 产物记录绝对路径，例如 `/home/dsy/...` 与 `/root/...` 不可混用。

## 2. 完整操作顺序

```text
检查宿主机
→ 下载匹配版本的kuavo-ros-opensource
→ 准备配套Docker镜像
→ 在容器内编译控制器
→ 在宿主机下载LeTools
→ 编译LeTools ROS工作空间
→ 安装SDK
→ dry-run
→ 在容器内设置ROBOT_VERSION并启动MuJoCo
→ 在宿主机运行LeTools示例
```

## 3. 宿主机准备

### 3.0 硬件边界

客户验收所需的“官方最低配置”尚无仓库内实测记录，因此不能把未经验证的数值写成保证。发布负责人应在目标镜像和典型场景上完成基准测试后替换下表中的“待确认”。

| 工作内容 | CPU | 内存 | 可用磁盘 | GPU | 当前结论 |
|---|---|---|---|---|---|
| 阅读、编辑、JSON静态检查 | 待确认 | 待确认 | 待确认 | 不需要 | 无GPU可完成 |
| 行为树 dry-run | 待确认 | 待确认 | 待确认 | 不需要 | 无GPU可完成，不验证ROS和运动 |
| 编译LeTools消息包和SDK | 待确认 | 待确认 | 至少预留10 GB作为自检警戒线 | 不需要 | 性能影响耗时，不改变编译语义 |
| MuJoCo基础仿真 | 待实测 | 待实测 | 待实测 | 可选 | CPU可运行能力及帧率待目标镜像验收 |
| GPU视觉/高负载仿真 | 待实测 | 待实测 | 待实测 | NVIDIA及Container Toolkit | 型号和显存下限待实测 |

因此，低配置或无GPU主机仍可完成代码开发、静态检查、单元测试和 dry-run；不能据此宣称视觉帧率、实时控制或完整MuJoCo场景通过。具体场景是否支持 MuJoCo，应以场景目录内的 README 和实际验证记录为准。

### 3.1 基础环境

```bash
lsb_release -a
source /opt/ros/noetic/setup.bash
rosversion -d
python3 --version
git --version
catkin --version
docker --version
```

预期：Ubuntu 20.04、ROS输出 `noetic`、Python为3.8或更高。

安装常用依赖：

```bash
sudo apt update
sudo apt install -y python3-pip python3-rosdep python3-catkin-tools python3-empy python3-catkin-pkg python3-rospkg libgflags-dev unzip
python3 -m pip install --upgrade "numpy>=1.19.5,<1.27.0"
```

如果提示符含 `(base)`，先退出 Conda，避免 ROS Noetic 调用 Conda Python：

```bash
conda deactivate
which python3
```

推荐 `which python3` 输出 `/usr/bin/python3`。

### 3.2 NVIDIA GPU（可选）

只有使用 NVIDIA GPU 容器时才需要检查：

```bash
nvidia-smi
nvidia-ctk --version
docker info | grep -i runtime
```

若 Docker 的 Runtimes 已包含 `nvidia`，不需要重复安装或配置 NVIDIA Container Toolkit。`nvidia-ctk runtime configure` 必须在宿主机执行，不是在容器内执行。普通仿真足够流畅时可以继续使用 `docker/run.sh`。

## 4. 获取正确版本的 kuavo-ros-opensource

`1.4.5` 是 Tag，不是分支。建议单独克隆，避免复用其他版本的编译缓存：

```bash
cd "$HOME"
git clone --branch 1.4.5 --single-branch --recurse-submodules https://gitcode.com/OpenLET/kuavo-ros-opensource.git kuavo-ros-opensource-1.4.5
cd "$HOME/kuavo-ros-opensource-1.4.5"
git describe --tags --exact-match
git rev-parse --short HEAD
```

第一条版本检查应输出 `1.4.5`。

> 代码Tag、Docker镜像和OpenVINO必须配套。旧资料中的 `kuavo_opensource_mpc_wbc_img:1.3.0` 不应在未验证兼容性的情况下作为1.4.5正式环境。

## 5. 进入Docker并编译控制器

在宿主机执行：

docker 镜像可以自行查看网上相关配置使用 ./docker/Dockerfile 构建，或者下载已经编译好的镜像：
wget https://kuavo.lejurobot.com/kuavo_research_editiion/docker_images/kuavo_opensource_mpc_wbc_img_v1.3.0.tar.gz

执行以下命令导入容器镜像：
sudo docker load -i kuavo_opensource_mpc_wbc_img_v1.3.0.tar.gz

💡 （推荐）进入 kuavo-ros-opensource 目录执行 ./docker/run.sh 进入容器后，默认在仓库的映射目录 /root/kuavo_ws，执行以下命令开始编译：
cd "$HOME/kuavo-ros-opensource-1.4.5"
chmod +x docker/run.sh
./docker/run.sh
```

宿主机仓库通常会挂载为：

```text
/home/dsy/kuavo-ros-opensource-1.4.5 → /root/kuavo_ws
```

因此容器内显示 `/root/kuavo_ws` 是正常的；此时不要再执行 `cd kuavo-ros-opensource`。

在容器中确认：

```bash
pwd
git describe --tags --exact-match
ls
```

然后编译：

```bash
cd /root/kuavo_ws
source /opt/ros/noetic/setup.zsh
source installed/setup.zsh
catkin config -DCMAKE_ASM_COMPILER=/usr/bin/as -DCMAKE_BUILD_TYPE=Release
catkin build humanoid_controllers -p 1
```

`-p 1`让catkin一次只调度一个包，可降低首次构建时“依赖正在安装、下游已经开始链接”的竞态风险。

### 5.1 OpenVINO检查

按依赖顺序补编译：

```bash
cd /root/kuavo_ws
source /opt/ros/noetic/setup.zsh
source installed/setup.zsh
catkin build kuavo_assets -p 1
source devel/setup.zsh
catkin build humanoid_interface_ros -p 1
source devel/setup.zsh
catkin build humanoid_wheel_interface_ros -p 1
source devel/setup.zsh
catkin build humanoid_controllers -p 1
```

## 7. 在宿主机编译LeTools ROS工作空间

### 7.1 加载环境

```bash
source /opt/ros/noetic/setup.bash
source "$HOME/kuavo-ros-opensource-1.4.5/installed/setup.bash"
cd "$HOME/letools_opensource/infrastructure/ros_packages"
```

配置明确继承1.4.5：

```bash
catkin config --extend "$HOME/kuavo-ros-opensource-1.4.5/installed" -DCMAKE_ASM_COMPILER=/usr/bin/as -DCMAKE_BUILD_TYPE=Release
```

如果catkin警告缓存中的 `CMAKE_PREFIX_PATH` 与新路径不同，先确认当前目录正确，再清理生成物：

```bash
pwd
catkin clean -y
```

### 7.2 跳过暂不使用的视觉包

为避免复制多行命令时因空行导致 `command not found`，这里使用单行命令：

```bash
catkin config --skiplist detection_yolo_v8 ar_control kuavo_vision_object kuavo_yolo_point2d yolo_box_object_detection yolo_button_object_detection yolo_valve_object_detection orbbec_camera realsense2_camera kuavo_camera
catkin build
```

编译成功后：

```bash
source devel/setup.bash
python3 -c 'import kuavo_msgs; import ocs2_msgs; print("ROS messages ready")'
```

若出现 `gflags/gflags.h: 没有那个文件或目录`：

```bash
sudo apt install -y libgflags-dev
catkin build
```


## 8. 安装LeTools SDK

```bash
cd "$HOME/letools_opensource"
source infrastructure/ros_packages/devel/setup.bash
chmod +x scripts/install_sdk.sh
./scripts/install_sdk.sh
python3 -c 'from kuavo_humanoid_sdk import KuavoRobot; print("SDK Ready")'
```

不要把删除 `drivers/leju/kuavo_humanoid_sdk` 作为默认步骤。只有确认子模块损坏、没有本地修改并已备份时才清理。



## 9. 启动MuJoCo

进入Docker容器，在容器内设置与目标模型匹配的版本：

```bash
cd /root/kuavo_ws
export ROBOT_VERSION=62
echo "$ROBOT_VERSION"
source devel/setup.zsh
roslaunch humanoid_controllers load_kuavo_mujoco_sim_wheel.launch
```

`62`表示机器人配置版本6.2，只是常用示例，不是SDK版本。必须按目标机器人选择。

若当前容器使用zsh，可写入 `~/.zshrc`：

```bash
grep -qxF 'export ROBOT_VERSION=62' ~/.zshrc || echo 'export ROBOT_VERSION=62' >> ~/.zshrc
```

容器重建后该文件可能丢失；长期使用可在Docker启动参数中加入 `-e ROBOT_VERSION=62`。

Oh My Zsh访问GitHub更新失败与ROS、MuJoCo无关，更新询问可直接选择 `n`。

## 10. 从宿主机运行LeTools示例

保持容器中的MuJoCo终端运行，在宿主机新开终端：

```bash
conda deactivate 2>/dev/null || true
cd "$HOME/letools_opensource"
source /opt/ros/noetic/setup.bash
source infrastructure/ros_packages/devel/setup.bash
export PYTHONPATH="$(pwd):${PYTHONPATH}"
rosnode list
rosservice list | grep mobile_manipulator
python3 apps/test_kuavo_5w_sdk_adapter/sdk/01_head/test_head_control.py
```

若宿主机看不到容器中的ROS节点，检查Docker是否使用host网络，并检查双方的 `ROS_MASTER_URI`。

## 11. 能力边界

| 阶段 | 可以验证 | 不能证明 |
|---|---|---|
| dry-run | Python、JSON、节点、子树、board | ROS服务和运动 |
| MuJoCo | ROS/SDK链路、时序、数据流、部分运动 | 真实安全、负载、视觉和抓取精度 |
| 真机 | 动力学、负载、精度、安全和稳定性 | - |

`jibot_nav`等场景依赖JiBot调度服务，没有等价仿真实现时不能直接在MuJoCo运行。fake tag只能验证后续流程，不能证明真实视觉通过。

## 13. 常见错误速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `cd kuavo-ros-opensource: no such file` | 容器内仓库名是挂载点 `/root/kuavo_ws` | 留在 `/root/kuavo_ws` |
| `-v: command not found` | `-v`是`docker run`参数，不是独立命令 | 写入Docker启动参数 |
| `--workspace: command not found` | 反斜杠后插入空行，命令被拆开 | 使用本文单行命令 |
| catkin显示错误Workspace | 两个catkin工作空间嵌套或缓存路径错误 | 分离仓库并清理对应工作空间缓存 |
| Resultspace path不存在 | `.catkin_tools`保留了旧绝对路径 | 修正`extend_path`并`catkin clean -y` |
| 找不到`empy` | Conda Python覆盖ROS系统Python | 退出Conda并安装`python3-empy` |
| 找不到`gflags/gflags.h` | 宿主机缺少开发包 | 安装`libgflags-dev` |
| `libopenvino.so.2520`不存在 | 控制器与镜像OpenVINO版本不一致 | 使用配套镜像或一致环境重编译 |
| `libkuavo_assets.so`不存在 | 首次并行构建发生依赖竞态 | 按5.1节串行补编译 |
| Oh My Zsh更新失败 | 容器无法连接GitHub | 选择`n`，不影响仿真 |

- [ ] dry-run通过；
- [ ] `ROBOT_VERSION`与目标模型一致；
- [ ] MuJoCo控制器启动且关键ROS服务存在；
- [ ] 至少一个LeTools示例在MuJoCo中运行成功。

## 15. 待项目维护者确认

- 1.4.5官方配套Docker镜像名称和下载地址；
