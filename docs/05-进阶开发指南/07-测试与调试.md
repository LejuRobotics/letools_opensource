# 07 测试与调试

测试按 dry-run → 单元测试 → 仿真 → 受控真机的顺序进行，每一步都需要明确的通过判据。

## 一、pytest 配置与已知问题

`pytest.ini` 的关键配置：

| 项 | 值 |
|---|---|
| `testpaths` | `tests` / `core/common/tests` / `adapters/hardware/leju_wheeled/services/sdk_manager/tests` / `adapters/hardware/leju_wheeled/tests` |
| `python_files` | `test_*.py` |
| `addopts` | `-v --tb=short --strict-markers --disable-warnings` |
| `log_cli` | `true`，`log_cli_level = INFO` |
| `markers` | `unit` / `integration` / `slow` |

### 已知问题：`testpaths` 覆盖不全

`testpaths` 当前只列了 **4 条**，而仓库实际存在的测试目录远多于此。实测（`find . -type d -name tests`，排除 `.git`）共 **21 个 `tests/` 目录**，其中属于 LeTools 自有代码的有：

```text
tests                                     ← 已在 testpaths
core/common/tests                         ← 已在 testpaths
adapters/hardware/leju_wheeled/tests      ← 已在 testpaths
adapters/hardware/leju_wheeled/services/sdk_manager/tests
orchestration/engine/tests                ← 未列入
orchestration/nodes/tests                 ← 未列入
orchestration/nodes/utils/tests           ← 未列入
adapters/hardware/leju_wheeled/mixins/tests ← 未列入
skills/atomic/perception/{box_frame,pallet_detect,pallet_frame,pallet_servo}/tests ← 未列入
```

其余为第三方依赖自带（`infrastructure/ros_packages/src/**` 等）或构建产物，不属本文范围。

**后果**：直接跑 `pytest` **不会拾起未列入的那些目录**，它们会被静默跳过。当前规避方式是显式给路径：

```bash
pytest orchestration/nodes/tests orchestration/engine/tests
pytest skills/atomic/perception/pallet_servo/tests
pytest adapters/hardware/leju_wheeled/mixins/tests
```

> 当前 `pytest.ini` 的 `testpaths` 共列出 4 个目录。默认测试范围以该配置为准；
> 其他目录的测试请显式指定路径。若要扩展默认收集范围，需先评估新增测试的依赖和运行环境。

### 前置条件：先装好 SDK 子模块

裸跑 `pytest` 在纯净 checkout 上**会在 collection 阶段直接报错退出**，而不是只用例变红：

```text
ModuleNotFoundError: No module named 'kuavo_humanoid_sdk'
ERROR adapters/hardware/leju_wheeled/services/sdk_manager/tests/test_arm_sdk_manager.py
...(共 4 个 ERROR)
Interrupted: 4 errors during collection !!!
```

`testpaths` 里的 `adapters/hardware/leju_wheeled/services/sdk_manager/tests/` 四个文件都在模块顶层
`import kuavo_humanoid_sdk`，而该包由 submodule `drivers/leju/kuavo_humanoid_sdk` 提供（开源产物中排除）。
**先跑 `bash scripts/install_sdk.sh`，并把生成目录加进 `PYTHONPATH`**，`pytest` 才跑得起来。
只想验文档站的 `tests/` 时可绕开：`pytest tests/`。

## 二、markers

| marker | 含义 | 运行方式 |
|---|---|---|
| `unit` | 单元测试，不需要实机 | `pytest -m unit` |
| `integration` | 集成测试，需要仿真或实机 | `pytest -m integration` |
| `slow` | 慢速测试，耗时较长 | 默认跑，必要时 `-m "not slow"` 排除 |

`--strict-markers` 已开启：**用未在 `markers` 中声明的 marker 会直接报错**，新增 marker 必须同时登记到 `pytest.ini`。

## 三、日志与故障定位

- 统一用 `core/common/logger.py` 的 `init_logging()` + `get_logger(__name__)`，**禁止 `print()`**（`apps` 的薄启动器除外，它用 `print` 输出给用户看的结果）；
- `pytest.ini` 已开 `log_cli`，测试期间日志直出到控制台；
- 服务等待、运动等待都要有超时并打印上下文；**不要静默吞异常**。

## 四、三级判定清单

| 级别 | 命令 | 通过判据 |
|---|---|---|
| 1. dry-run | `python3 apps/test_upper_init/run_behavior_tree_json.py --scenario <dir> --dry-run --tick-once` | 输出 `tick 后根状态: Status.SUCCESS`；无 import / 类名 / JSON / 子树 key 错误（dry-run 退出码只反映加载是否成功） |
| 2. 单测 | `pytest`（**需先装 SDK 子模块**，见第一节；未拾起目录显式给路径） | 全绿；`--strict-markers` 下无未声明 marker |
| 3. 仿真 | `python3 .../run_behavior_tree_json.py --scenario <dir>`（需先起 ROS 与运控站立链） | 行为树跑完，末态 `SUCCESS`；观测量符合预期 |
| 4. 真机 | 同上，受控条件 | 在仿真通过后再上；动作在安全范围内 |

dry-run 的机制（`STUDIO_DRY_RUN=1`、不初始化 ROS/硬件、运动节点与 `WaitForEnter` 直接返回 `SUCCESS`）见 `05-05-扩展-orchestration-层`。**成功判定以退出码为准**：`SUCCESS=0`、`FAILURE=1`、其它 `=2`。

## 五、常见故障排查手册

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 启动即报「主树 py_tree.json 不存在」 | `--scenario` 目录下缺 `py_tree.json` | 核对场景目录与文件名 |
| 读取 `board.json` 失败 | 路径错误或 JSON 语法错误 | `python3 -m json.tool board.json` 校验 |
| 非 ROS 环境启动报错 | 未用 dry-run | 加 `--dry-run`，或补 `py_trees` 依赖 |
| `--action-groups` 报格式错误 | 传参不是逗号分隔数字 | 改为如 `1,3,5` |
| 硬件预热失败后退出（码 1） | ROS / 下位机 / 硬件未就绪 | 查看预热异常信息；仿真阶段先用 dry-run |
| dry-run 加载失败：root 不存在 | 树构建失败（类名/子树 key 错误） | 检查 `name` 是否为有效类名或已定义子树 key |
| `[V3.0 Lite Interface Error]` 必填参数缺失 | `interface` 必填项无 override / 黑板 / default | 传 override、设黑板 `external_key`、或补 `default` |
| `[V3.0 Lite Type Error]` | 值无法转换为声明的 `data_type` | 核对值的格式与类型 |
| `[V3.0 Lite Enum Error]` | 值不在 `options` 允许列表 | 改用允许值之一 |
| `[V3.0 Lite Macro] 警告: 变量未在 interface 中定义` | `${var}` 未在 `interface.inputs` 声明 | 补声明或修正变量名 |
| `Unknown composite node type` | `name` 写成未支持的复合类型 | 只支持 `Sequence` / `Selector` / `Parallel` |
| `py_trees` 版本不兼容 | 未先导入兼容层 | 确认启动器先 `import py_trees_compat` |

> 表中前几条的现象与判据来自启动器与应用层的实际报错路径，错误码前缀来自引擎的 `<V3.0 Lite …>` 校验分支。
