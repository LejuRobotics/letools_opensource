# 01 系统要求

[返回文档首页](../README.md) · [01-介绍](../01-介绍/) · [02-环境安装](../02-环境安装/)

> 本篇只回答一个问题：**装之前，机器上应当先有什么**。
> 具体怎么装见 [`03-安装步骤.md`](03-安装步骤.md)；装不起来的报错见
> [`../06-常见问题FAQ/01-安装与环境.md`](../06-常见问题FAQ/01-安装与环境.md)。

推荐基线是 **Ubuntu 20.04 + ROS Noetic + Python 3.8+**，这也是项目**唯一被完整验证过**的组合；
其它环境需要自行验证，不能默认兼容。

## 一、推荐基线

| 项 | 推荐值 | 为什么是它 |
|---|---|---|
| 操作系统 | **Ubuntu 20.04** | ROS Noetic 的主要目标平台；仓库全部依赖（消息包、catkin、相机驱动）都在此平台上验证 |
| ROS | **ROS Noetic**（ROS1） | 本项目走 ROS1 的话题 / 服务 / TF；无 ROS2 支持 |
| Python | **Python 3.8+**（系统 Python 3） | Noetic 的 Python 绑定是 3.8；`python3` 必须指向 `/usr/bin/python3` |
| 编译工具 | **catkin（推荐 `catkin build`）** | 两个 catkin 工作空间都要用；`catkin_tools` 需单独安装 |
| SDK | **`kuavo_humanoid_sdk`** | 作为 submodule 挂在 `drivers/leju/kuavo_humanoid_sdk`，版本由仓库锁定，见 [`05-升级与卸载.md`](05-升级与卸载.md) |
| Docker | **仿真必需** | 仿真时 kuavo-ros-opensource、MuJoCo 和控制器运行在 Docker 容器中，LeTools 运行在宿主机，见 [`03-安装步骤.md`](03-安装步骤.md) 的 1.1；真机部署不需要 |
| MuJoCo | 仿真需要 | 随容器中的 kuavo-ros-opensource 提供，不需要在宿主机单独安装；真机部署不需要 |

> ⚠️ **必须设置 `ROBOT_VERSION`**。它不是 SDK 版本，而是机器人硬件代次（如 `45`、`62`、`63`），
> 决定使用哪套 URDF 模型与配置目录（`kuavo_v62` 等）。**没设置就会加载错模型或直接启动失败**：
>
> ```bash
> export ROBOT_VERSION=62     # 62 夹爪轮臂示例；63 轮臂用 63，按目标机器人选择
> echo "$ROBOT_VERSION"
> ```
>
> 仿真启动前设置，见 [`03-安装步骤.md`](03-安装步骤.md) 的「1.2 MuJoCo 仿真验证」。

### 项目支持范围与上游维护状态

以下两件事需要分开看：

| 项 | 状态 |
|---|---|
| 项目实际测试与支持的环境 | Ubuntu 20.04 + ROS Noetic + Python 3.8。2026-10-31 在 Ubuntu 20.04.6 / ROS Noetic / Python 3.8.10 / NumPy 1.24.4 的开发机上实测 dry-run 通过 |
| 上游官方维护状态 | ROS Noetic 已于 **2025-05-31** 结束官方支持（EOL）；Ubuntu 20.04 LTS 的标准支持也已于 2025 年结束，之后仅有 Canonical 的付费扩展维护（ESM） |

上游 EOL 不意味着 LeTools 必须立即迁移，现有教程仍按 20.04 + Noetic 编写和验证。但需注意：

- 上游不再发布 Noetic 的缺陷与安全修复，apt 源中的包版本基本固定；
- LeTools 目前**没有** ROS 2 或其他发行版的适配与验证计划记录；迁移目标与时间由项目维护者决定；
- 面向生产环境部署时，建议在网络隔离、镜像固化等方面自行评估风险。

## 二、硬件边界：各部分机器承担什么工作

「一台机器人」实际上是多台计算机组成的系统，装环境时要分清自己在哪一台、哪一台才是瓶颈。

| 角色 | 承担的工作 | 环境要求要点 |
|---|---|---|
| **上位机**（跑 LeTools） | 行为树编排、技能、感知、规划、SDK 调用 | 需要完整装好 ROS + Python 依赖 + catkin 工作空间 + SDK；是**编译最重**的一台 |
| **下位机**（运控） | MPC / WBC 实时控制、关节伺服、MuJoCo 仿真器 | 跑 `kuavo-ros-opensource`；真机上是**另行就绪**的设备，上位机不重复部署它 |
| **CPU** | 编译、catkin 构建、行为树 tick、Python 逻辑 | 编译期是主要负载；构建建议串行单包（`catkin build <pkg> -p 1`）以避免依赖竞态 |
| **内存** | 编译 + 仿真 + 行为树同时驻留 | 内存不足时优先表现为编译被杀（OOM），可用 `catkin build <包名> -p 1` 降低并发 |
| **磁盘** | 两个工作空间 + Docker 镜像 + 编译产物 | 自检脚本以 **项目盘剩余 ≥ 10 GB** 为阈值（不足报 `W012`）；含 Docker 镜像时需求更大 |
| **GPU** | 仅 GPU 加速的仿真 / 容器需要 | **可选**。无 GPU 仍可完成编辑、静态检查、单测与 dry-run（自检报 `W011`，非阻断） |

> **上位机是唯一必须完整装环境的机器**；下位机与底盘在真机场景中是已经就绪的外部设备，
> 通过 ROS 网络被访问，不需要在上面装 LeTools。

## 三、被明确排除的环境

| 环境 | 结论 | 说明 |
|---|---|---|
| Windows / macOS 直接运行 | ✗ 不支持 | 自检第一项即检查 Linux（`E001`）；Windows 只用于阅读文档与静态编辑 |
| WSL | ✗ 不支持 | ROS 网络、Docker GPU 与设备访问均不稳定；请使用 Ubuntu 20.04 宿主机 |
| Conda 环境里编译 ROS | ✗ 不允许 | Conda 的 Python 会覆盖系统 Python，catkin 找不到 `catkin_pkg` / `empy`；编译前 `conda deactivate`（自检报 `W002`） |
| ROS2 / 非 Noetic 发行版 | ✗ 不支持 | 消息包与话题均为 ROS1 Noetic 形态 |
| Python 3.7 及以下 | ✗ 不支持 | 自检检查 `sys.version_info >= (3, 8)`（`E004`） |
| 两个 catkin 工作空间互相嵌套 | ✗ 不允许 | 会互相污染缓存；LeTools 的工作空间应 `catkin config --extend` 到上游 `installed`，而不是嵌进去 |

## 四、非 Ubuntu 20.04 怎么办

目前**不支持**宿主机为非 Ubuntu 20.04 的部署：LeTools 需要在宿主机上用 ROS Noetic 编译和运行，Docker 容器只承载 kuavo-ros-opensource、MuJoCo 和控制器，见 [`03-安装步骤.md`](03-安装步骤.md) 的 1.1。

其他组合（例如把 LeTools 也放进容器、在其他发行版上自行编译 ROS Noetic）未经项目验证。如果自行尝试，需要注意：

- 镜像与控制器必须 **OpenVINO 版本一致**，否则出现 `libopenvino.so.2520` 找不到，判断方法见
  [`../06-常见问题FAQ/01-安装与环境.md`](../06-常见问题FAQ/01-安装与环境.md) 的 2.3；
- 宿主机与容器生成的工作空间 **不得混用**；
- 必须按 [`04-环境验证.md`](04-环境验证.md) 跑完四类验证，且至少有一个 LeTools 示例在仿真中跑通，才能认为该环境可用。

## 五、装之前的三项确认

```bash
# 1) 在哪个环境（宿主机还是容器）
whoami; hostname; pwd; python3 -c 'import sys; print(sys.executable)'

# 2) 系统与 ROS 版本
lsb_release -a
ls /opt/ros/                  # 期望看到 noetic

# 3) 一键只读自检（不安装、不修改任何东西）
cd /path/to/letools_opensource
bash scripts/check_environment.sh
```

自检退出码：`0` 无阻断项；`1` 有必须修复项；`--strict` 下仍有警告则 `2`。
逐条代码含义见 [`../06-常见问题FAQ/01-安装与环境.md`](../06-常见问题FAQ/01-安装与环境.md) 的 0.2 节。
