# 02 依赖版本清单

[返回文档首页](../README.md) · [01-介绍](../01-介绍/) · [02-环境安装](../02-环境安装/)

> 本篇列出 LeTools 在每个环境层面分别依赖什么、版本由谁决定、装错了会怎样。
> 具体安装命令见 [`03-安装步骤.md`](03-安装步骤.md)。

LeTools 的依赖分四层：**自有 Python 依赖（版本由 `requirements.txt` 决定）→ 系统 / ROS 包依赖 →
SDK 依赖（版本由 `sdk_version.env` 锁定）→ 可选相机 / GPU 依赖**。
**凡是仓库里有版本锁的（`requirements.txt`、`sdk_version.env`），就照锁装；不要自己挑版本。**

## 一、LeTools 自有 Python 依赖

LeTools 自有运行时依赖列在仓库根目录的 `requirements.txt` 中，当前三个包：

| 包 | 用途 | 版本约束 |
|---|---|---|
| `colorlog` | 统一日志的彩色输出 | **不固定**（跟随上游最新兼容版） |
| `py_trees` | 行为树运行时（树实例的承载库） | **不固定**；`orchestration/engine/py_trees_compat.py` 已做 **0.7.x / 2.x 双向兼容** |
| `scipy` | 位姿 / 旋转换算（`core/common/transform.py` 等使用 `Rotation.from_matrix`） | `>=1.4`：Ubuntu 20.04 自带的 `python3-scipy` 1.3.3 没有 `from_matrix`，会在运行期抛 `AttributeError` |

安装：

```bash
cd ~/letools_opensource
pip3 install -r requirements.txt
```

> SDK 子模块自身的依赖由 `scripts/install_sdk.sh` 安装，不在 `requirements.txt` 中。

## 二、系统与 ROS 包依赖

| 依赖 | 用途 | 安装方式 | 缺失时 |
|---|---|---|---|
| `python3-pip` | 安装 Python 包 | `apt` | 无法 `pip install` |
| `python3-catkin-tools` | `catkin build` 命令 | `apt` | 只能退回 `catkin_make`，与文档命令不符（自检 `W001`） |
| `python3-empy` | ROS 消息生成（`em` 模块） | `apt` | 编译报 `Unable to find either executable 'empy' or Python module 'em'` |
| `python3-catkin-pkg` / `python3-rospkg` | catkin 的 Python 元数据 | `apt` | 报 `No module named catkin_pkg` / `rospkg` |
| `libgflags-dev` | C++ 包的 gflags 头文件 | `apt` | 报 `fatal error: gflags/gflags.h: No such file or directory` |
| `unzip` | 解压预制资源 | `apt` | 解压步骤失败 |
| ROS Noetic（含 `/opt/ros/noetic/setup.bash`） | 消息 / 服务 / TF | 官方 apt 源 | 自检 `E003` |

一条命令装齐：

```bash
sudo apt update
sudo apt install -y python3-pip python3-rosdep python3-catkin-tools python3-empy \
  python3-catkin-pkg python3-rospkg libgflags-dev unzip
```

## 三、`numpy` 版本约束

`numpy` **不在**两份 `requirements.txt` 里，它对上游 ROS 包的 ABI 敏感，需要单独约束：

```bash
python3 -m pip install --upgrade "numpy>=1.19.5,<1.27.0"
```

| 边界 | 数值 | 原因 |
|---|---|---|
| 下限 | `>= 1.19.5` | 上游 ROS / 视觉包要求 |
| 上限 | `< 1.27.0` | 把 NumPy 限制在 1.x 系列，避开 2.0 的 ABI 变化 |

NumPy 没有发布 1.27，1.26.x 之后的下一个版本是 2.0，因此 `< 1.27.0` 的实际效果是「不安装 NumPy 2.x」。
需要关注的 ABI 兼容性断点是 **NumPy 2.0**：针对 NumPy 1.x 编译的 C 扩展（如上游 ROS / 视觉包中的扩展模块）在 2.x 下 import 时可能报错。
另外，Python 3.8 可安装的 NumPy 最高为 1.24.x，在推荐基线上该上限通常不会被触发。

自检脚本 `scripts/check_environment.sh` 按同一范围检查（不满足报 `W003`）。
2026-10-31 在 Ubuntu 20.04.6 + ROS Noetic + Python 3.8.10 的开发机上，实际版本为 `numpy 1.24.4`。

> 误装 NumPy 2.x 的典型症状是「某 ROS 包 import 时出现 numpy ABI 相关报错」。
> 处理方式：重新执行上面的安装命令把 NumPy 降回 1.x，再运行 `bash scripts/check_environment.sh` 确认不再出现 `W003`。

## 四、SDK 依赖（版本由仓库锁定）

SDK 不是「随 pip 装的最新版」，而是**由仓库锁定的配套版本**，来源是另一个仓库
`kuavo-ros-opensource`。

| 项 | 值 / 位置 | 说明 |
|---|---|---|
| 锁文件 | `scripts/kuavo_humanoid_sdk_tools/sdk_version.env` | 随仓库发版，被 git 跟踪 |
| 当前配套分支 | `SDK_REPO_BRANCH="master"` | 必须与 tag 配对 |
| 当前配套 tag | `SDK_REPO_TAG="1.4.5"` | 必须**是**该分支上的 tag |
| 代码位置 | `drivers/leju/kuavo_humanoid_sdk`（submodule） | 开源产物中排除，由用户运行 `scripts/install_sdk.sh` 安装 |
| 本地临时覆盖 | `scripts/kuavo_humanoid_sdk_tools/sdk_config.sh` | 默认空即用配套版本；`sdk_config.sh` 已被 `.gitignore` 忽略 |

**为什么必须配对**：`install_sdk.sh` 在安装前会用 `git merge-base --is-ancestor` 校验
「tag 确实是该分支的祖先」，不通过直接退出。避免出现「装了别的分支上的同名 tag」这种极难排查的错配。

**版本不一致的典型后果**：话题订阅失败、消息 `md5sum` 不一致，甚至段错误
（`kuavo_msgs` / `ocs2_msgs` 在多个仓库中有副本，md5 不一致订阅就断）。

升级 / 回退 / 卸载见 [`05-升级与卸载.md`](05-升级与卸载.md)。

## 五、可选依赖：相机 / 视觉 / GPU

| 依赖 | 何时需要 | 备注 |
|---|---|---|
| `orbbec_camera`（ROS 包） | 用头部 Orbbec 相机 | `config/camera_config.yaml` 的 `head_camera_type` 可为 `orbbec_camera` / `realsense2_camera` |
| `realsense2_camera`（ROS 包） | 用腕部 RealSense 相机（左右腕共用） | 需要时另装 `librealsense2-dev librealsense2-utils`，apt 找不到包要先配 Intel RealSense 源 |
| `detection_yolo_v8`、`ar_control`、`kuavo_vision_object` 等视觉包 | 需要 YOLO / AprilTag 检测 | **只做 SDK、行为树或无视觉仿真时可跳过**，见下方 skip 清单 |
| NVIDIA 驱动 + Container Toolkit | 仅 GPU 加速仿真 / GPU 容器 | 无 GPU 仍可 dry-run、单测、静态检查 |
| 与镜像一致的 OpenVINO | 控制器依赖 | **必须与配套 Docker 镜像一致**，否则 `libopenvino.so.2520` 找不到；不要用软链接伪装不同 ABI |
| MuJoCo | 仿真调试 | 随 `kuavo-ros-opensource` 提供，非独立 pip 包 |

**暂不需要视觉时的 skip 清单**（`config/camera_config.yaml` 中把对应开关关掉，并把 ROS 包加入 skiplist）：

```bash
cd ~/letools_opensource/infrastructure/ros_packages
catkin config --skiplist \
  detection_yolo_v8 ar_control \
  kuavo_vision_object kuavo_yolo_point2d \
  yolo_box_object_detection yolo_button_object_detection yolo_valve_object_detection \
  orbbec_camera realsense2_camera kuavo_camera
catkin build
```

> ⚠️ **不要跳过 `kuavo_tf2_web_republisher`**：它是坐标链服务，行为树依赖它。

## 六、快速核对表

| 层 | 版本从哪来 | 要点 |
|---|---|---|
| LeTools Python | 仓库根 `requirements.txt` | `colorlog`、`py_trees`、`scipy>=1.4` |
| 系统 / ROS | `apt` | catkin-tools / empy / gflags 缺一不可 |
| `numpy` | 手动约束 | `>=1.19.5,<1.27.0` |
| SDK | `sdk_version.env` | `master` + `1.4.5`，随 LeTools 发版更新 |
| 相机 / GPU | 按需 | 不用视觉可 skip；OpenVINO 必须与镜像配套 |

装完后逐项验证见 [`04-环境验证.md`](04-环境验证.md)；自检脚本 `bash scripts/check_environment.sh`
会检查其中可自动判定的部分（SDK 锁文件不完整报 `E005`）。
