# 04 环境验证

[返回文档首页](../README.md) · [01-介绍](../01-介绍/) · [02-环境安装](../02-环境安装/)

本文中的相对路径（如 `apps/`、`scripts/`、`infrastructure/ros_packages/`）
一律相对 **LeTools 仓库根目录**，需在仓库根目录下执行；文中 `/root/kuavo_ws`、`/opt/ros/...`
属下位机 / 系统侧工作空间，不属本仓库，路径以各自环境实际位置为准。

> 装完不等于装对。本篇给出**四类验证**，按顺序做，每一步都有明确的「通过标准」。
> 报错处理不在本篇，见 [`../06-常见问题FAQ/01-安装与环境.md`](../06-常见问题FAQ/01-安装与环境.md)
> 与 [`../06-常见问题FAQ/03-SDK-与版本.md`](../06-常见问题FAQ/03-SDK-与版本.md)。

从**最便宜**的验证做起：**自检脚本 → import 自检 → ROS 连通性 → 版本比对 → 仿真跑通**。
前一步未通过时不要进入下一步：越往后，报错信息越模糊，排查代价越高。

## 〇、先跑只读自检

```bash
cd /path/to/letools_opensource
bash scripts/check_environment.sh
echo $?
```

| 退出码 | 含义 | 下一步 |
|---|---|---|
| `0` | 无阻断项 | 继续下面第一类验证 |
| `1` | 有必须修复项（`E00x`） | 先按 [`../06-常见问题FAQ/01-安装与环境.md`](../06-常见问题FAQ/01-安装与环境.md) 的 0.2 代码表处理 |
| `2` | 严格模式下仍有警告（`--strict`） | 警告不阻断，按需处理 |

自检**只读**，不安装、不修改任何东西，可以随时重跑。

## 一、`import` 自检

### 1.1 ROS 消息包

```bash
python3 -c 'import kuavo_msgs, ocs2_msgs; print("ROS messages ready")'
```

**通过标准**：输出 `ROS messages ready`。

> 这一步失败最常见的原因是**解释器不对**（Conda 抢占）或**工作空间没 source**：
> 先 `which python3` 确认是 `/usr/bin/python3`，再 `source infrastructure/ros_packages/devel/setup.bash`。
> ⚠️ `kuavo_msgs` / `ocs2_msgs` 在多个仓库中有副本，**md5sum 不一致会导致话题订阅失败**——
> 若 import 成功但话题收不到数据，检查消息包版本是否一致。

### 1.2 消息定义可用

```bash
rosmsg list | grep '^kuavo_msgs/'    # 列出 kuavo_msgs 包中的消息类型
```

**通过标准**：能列出 `kuavo_msgs` 下的消息类型；若为空，说明工作空间未 source。

### 1.3 Kuavo SDK

```bash
python3 -c 'from kuavo_humanoid_sdk import KuavoRobot; print("SDK Ready")'
```

**通过标准**：输出 `SDK Ready`。

```bash
python3 -c 'import kuavo_humanoid_sdk; print(kuavo_humanoid_sdk.__file__)'
python3 -m pip show kuavo-humanoid-sdk
```

两条命令应指向**同一个 Python 环境**。若 `pip show` 有包但 import 失败，属解释器不一致，处理见
[`../06-常见问题FAQ/03-SDK-与版本.md`](../06-常见问题FAQ/03-SDK-与版本.md) 第 3 节。

### 1.4 LeTools 自身可 import

```bash
cd ~/letools_opensource
export PYTHONPATH="$(pwd):${PYTHONPATH}"
python3 -c 'import core, adapters, skills, orchestration; print("LeTools imports OK")'
```

**通过标准**：输出 `LeTools imports OK`。

> 若 `adapters` 报错「找不到 `.py`」，注意开源产物中 `adapters/` 是 **`.pyc` 分发**：
> 正常 `import` 不受影响，但读不到源码。见
> [`../01-介绍/05-开发者调用路径.md`](../01-介绍/05-开发者调用路径.md) 第四节。

## 二、ROS 话题 / 服务连通性

前置：目标平台（仿真或真机）的运控已启动。

```bash
source /opt/ros/noetic/setup.bash
source infrastructure/ros_packages/devel/setup.bash
rosnode list
rostopic list | head -20
rosservice list | grep mobile_manipulator
```

**通过标准**：`rosservice list` 能看到 `/mobile_manipulator_mpc_control` 之类的服务
（自检脚本同样以这个服务作为「仿真/运控已起来」的判据，见其 `W010`）。

| 检查 | 命令 | 期望 |
|---|---|---|
| 节点在不在 | `rosnode list` | 能看到运控 / 控制相关节点 |
| 服务在不在 | `rosservice list \| grep mobile_manipulator` | 至少 1 条 |
| 话题有没有数据 | `rostopic echo -n1 /<话题>` | 有输出且不报超时 |
| TF 链在不在 | `rosrun tf tf_echo map base_link` | 持续输出平移/旋转 |
| 工作空间识别 | `rospack find kuavo_tf2_web_republisher` | 返回包路径 |

> **宿主机看不到容器的节点**时，先确认 Docker 是否用 host 网络，再核对双方 `ROS_MASTER_URI`。
>
> ⚠️ `kuavo_tf2_web_republisher` 是行为树依赖的坐标链服务，**不能 skip**；
> 启动方式见 [`03-安装步骤.md`](03-安装步骤.md) 的 3.6 节。

## 三、版本比对

三处版本必须**互相配套**，缺一处都会在运行期以难懂的方式爆出来。

| 项 | 查看位置 | 期望 |
|---|---|---|
| Kuavo SDK Tag | `cat scripts/kuavo_humanoid_sdk_tools/sdk_version.env` | `SDK_REPO_BRANCH` 与 `SDK_REPO_TAG` 成对，且 tag 属于该分支（自检 `E005` 检查完整性） |
| `kuavo-ros-opensource` Tag | 克隆时用的 tag（如 `git -C ~/kuavo-ros-opensource-1.4.5 describe --tags`） | **与上一条的 tag 一致**（如都是 `1.4.5`） |
| Docker 镜像 / 控制器 OpenVINO | `ldd /root/kuavo_ws/devel/lib/libnodelet_controller.so \| grep openvino` | 与镜像自带版本一致，**不出现 `not found`** |

```bash
# 一次看全
cd ~/letools_opensource
cat scripts/kuavo_humanoid_sdk_tools/sdk_version.env
git -C "$HOME/kuavo-ros-opensource-1.4.5" describe --tags 2>/dev/null
find /opt/intel /usr -name 'libopenvino.so*' 2>/dev/null
```

**通过标准**：SDK 锁文件的 tag 与 `kuavo-ros-opensource` 的 tag 一致；控制器已链接的 OpenVINO
在当前环境里能找到。

> `libopenvino.so.2520` 与 `...2330` 是**不同 ABI**，**不要用软链接伪装**。
> 版本不一致的成因与处理见 [`../06-常见问题FAQ/01-安装与环境.md`](../06-常见问题FAQ/01-安装与环境.md) 的 2.3。

## 四、仿真能否起来

四步：**设版本 → 起仿真 → 查服务 → 跑示例**。

```bash
# ① 设机器人版本（必须，且与目标模型一致；不是 SDK 版本）
cd /root/kuavo_ws                    # 在 Docker 容器内执行
export ROBOT_VERSION=62               # 62 夹爪轮臂示例；63 轮臂改为 63
echo "$ROBOT_VERSION"

# ② 起 MuJoCo 仿真（轮臂）
source devel/setup.zsh               # 容器默认使用 zsh
roslaunch humanoid_controllers load_kuavo_mujoco_sim_wheel.launch

# ③ 另开终端，从宿主机确认连通
conda deactivate 2>/dev/null || true
cd ~/letools_opensource
source /opt/ros/noetic/setup.bash
source infrastructure/ros_packages/devel/setup.bash
export PYTHONPATH="$(pwd):${PYTHONPATH}"
rosnode list
rosservice list | grep mobile_manipulator

# ④ 跑一个 LeTools 示例，看机器人在仿真里动起来
python3 apps/test_kuavo_5w_sdk_adapter/sdk/01_head/test_head_control.py
```

**通过标准**：仿真器与控制器起来、`/mobile_manipulator_*` 服务存在、
示例脚本运行后**在仿真中能看到对应部位活动**。

- 起不来的现象定位：仿真日志里找第一条 `not found`（动态库）或 `REQUIRED process`
  （详见 [`03-安装步骤.md`](03-安装步骤.md) 附录 B）；
- `ROBOT_VERSION` 与模型不匹配时，症状是加载错模型或直接启动失败——
  它决定 `kuavo_v<版本>` 配置目录，**必须与目标机器人一致**。

### 还在更早的档位：dry-run

连仿真都还没起时，先用 dry-run 挡掉 Python / JSON 层面的错：

```bash
python3 orchestration/main.py --dry-run --tick-once
```

dry-run **不初始化 ROS / 硬件**，只校验加载：Python import、JSON 结构、节点加载、子树 key。
能过 dry-run 说明代码层没问题，剩下的都是环境/链路问题。

## 五、验收清单

逐项打勾即可认为环境可用（与 [`03-安装步骤.md`](03-安装步骤.md) 附录 A 同口径）：

- [ ] `bash scripts/check_environment.sh` 退出码为 `0`（或仅剩不阻断的 `W`）
- [ ] `import kuavo_msgs, ocs2_msgs` 成功
- [ ] `from kuavo_humanoid_sdk import KuavoRobot` 成功，输出 `SDK Ready`
- [ ] LeTools 四层（`core` / `adapters` / `skills` / `orchestration`）可 import
- [ ] `rosservice list | grep mobile_manipulator` 有输出
- [ ] `kuavo_tf2_web_republisher` 可 `rospack find`
- [ ] SDK 锁文件 tag 与 `kuavo-ros-opensource` tag 一致
- [ ] 控制器链接的 OpenVINO 在当前环境存在
- [ ] `ROBOT_VERSION` 已设置且与目标模型一致
- [ ] MuJoCo 仿真启动成功，关键 ROS 服务存在
- [ ] 至少一个 LeTools 示例在仿真中运行成功
- [ ] dry-run 通过
