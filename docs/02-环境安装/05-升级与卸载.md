# 05 升级与卸载

[返回文档首页](../README.md) · [01-介绍](../01-介绍/) · [02-环境安装](../02-环境安装/)

> 本篇说明三件事：**怎么升级到新版本、怎么回退到锁定版本、怎么把 SDK 卸干净**。
> 首次安装见 [`03-安装步骤.md`](03-安装步骤.md)，装完的验证见 [`04-环境验证.md`](04-环境验证.md)。
> 文中 `scripts/`、`infrastructure/` 等相对路径一律相对 LeTools 仓库根目录，命令默认在仓库根目录执行。

**版本跟着锁文件走**：升级 = 拉新代码让 `sdk_version.env` 变新，再重跑安装脚本；
回退 = 把代码切回旧版本/旧 tag，同样重跑安装脚本。**不要手动 `git checkout` SDK 里的分支**。

## 一、脚本分工

SDK 相关脚本都在 `scripts/sdk_tools/` 下，每个都支持 `--help`：

| 脚本 | 用途 | 何时用 |
|---|---|---|
| `scripts/sdk_tools/install.sh` | **安装 SDK 的统一入口**：按 `sdk_version.env` 从远程仓库获取源码并安装 | 首次安装、升级、回退后重装 |
| `scripts/sdk_tools/version.sh` | 查看版本是否一致、列出可用版本、切换版本、恢复配套版本 | 排查版本问题、临时调试其他版本 |
| `scripts/sdk_tools/remove.sh` | 卸载 | 清理环境、彻底重装 |
| `scripts/sdk_tools/install_local.sh` | 安装本地已有的 SDK 源码，不访问远程仓库 | 无法访问远程仓库时 |

`install.sh` 的顺序是：读锁文件 → 检查 ROS 消息包是否已编译 → **校验 branch/tag 配对** →
获取 SDK 源码（只下载并检出 `src/kuavo_humanoid_sdk/*`，不拉取整仓；元数据损坏会自动修复）
→ 拷贝消息包并 `pip install -e`。

> ⚠️ **不要在 `drivers/leju/kuavo_humanoid_sdk` 里手动 `git fetch` / `git checkout`**。该目录是只含目标版本、
> 只有 SDK 目录文件的精简克隆，换版本一律走上面的脚本。在该目录里 `git status`、`git diff` 可正常使用；
> `git show`、`git log -p` 会报 `missing blob`，属于预期行为。

## 二、升级

### 2.1 升级 LeTools 本体（含 SDK）

```bash
cd ~/letools_opensource

# 1) 拉新代码；新版本的 sdk_version.env 会带来新的配套 SDK 版本
git pull

# 2) 看新的锁定版本是什么
cat scripts/sdk_tools/sdk_version.env

# 3) 先重编译 ROS 工作空间（消息包可能变了；SDK 安装时会从 devel 中取 kuavo_msgs / ocs2_msgs）
cd infrastructure/ros_packages
source /opt/ros/noetic/setup.bash
catkin build
source devel/setup.bash

# 4) 再按新锁重装 SDK
cd ~/letools_opensource
./scripts/sdk_tools/install.sh

# 5) 回归验证
cd ~/letools_opensource
./scripts/sdk_tools/version.sh           # 配套版本、源码版本、pip 版本应一致
bash scripts/check_environment.sh
python3 -c 'from kuavo_humanoid_sdk import KuavoRobot; print("SDK Ready")'
```

> ⚠️ **顺序不能反**：先编译消息包，再装 SDK。反过来时，SDK 会带上旧的消息定义，或因找不到消息包直接退出。
>
> ⚠️ **消息包变了必须重编译**。`kuavo_msgs` / `ocs2_msgs` 在多个仓库中有副本，
> **md5sum 不一致会导致话题订阅失败**，而这不会在 import 阶段报错。

### 2.2 只重装 SDK（LeTools 代码不变）

```bash
cd ~/letools_opensource
./scripts/sdk_tools/install.sh
```

脚本是幂等的：源码和 pip 中都已是目标版本时，只刷新消息包，几秒内结束，不重新下载也不重装；
需要强制重装时加 `--force`。

## 三、版本回退

### 3.1 回退到当前锁定的版本（最常见）

「装成了别的版本，想回到仓库配套的那一版」：

```bash
cd ~/letools_opensource

# 1) 看现状：配套版本、本地覆盖、源码版本、pip 安装版本，以及它们是否一致
./scripts/sdk_tools/version.sh

# 2) 清除本地覆盖（如果有），装回配套版本
./scripts/sdk_tools/version.sh reset
```

### 3.2 回退到 LeTools 的旧版本

```bash
cd ~/letools_opensource
git log --oneline -- scripts/sdk_tools/sdk_version.env   # 找旧版本的锁定值
git checkout <旧版本 commit 或 tag>

# 先重编译 ROS 工作空间，再装 SDK（顺序同 2.1）
cd infrastructure/ros_packages && source /opt/ros/noetic/setup.bash && catkin build && source devel/setup.bash
cd ~/letools_opensource
./scripts/sdk_tools/install.sh
```

回退后跑一遍 [`04-环境验证.md`](04-环境验证.md) 的验收清单。

### 3.3 临时切到其它 SDK 版本调试

**用 `version.sh use`，不要改 `sdk_version.env`**：前者把版本写进被 `.gitignore` 忽略的
`scripts/sdk_tools/sdk_config.sh`，后者随仓库发版。

```bash
cd ~/letools_opensource
./scripts/sdk_tools/version.sh list                      # 远程仓库有哪些 tag
./scripts/sdk_tools/version.sh use 1.4.4 --branch dev    # 切换并安装；--branch 省略时用配套分支
```

tag 必须属于该分支——安装前会用 `git merge-base --is-ancestor` 校验，不通过直接退出，配置也不会被改动：

```text
❌ tag 1.4.4 不在分支 dev 上（或不是该分支的祖先）
```

只想装一次、不留下配置时，用 `./scripts/sdk_tools/install.sh --tag 1.4.4 --branch dev`。

调试完请执行 **`./scripts/sdk_tools/version.sh reset`**，否则后续升级会一直装着临时版本而不自知。
`version.sh` 的输出里会明确列出「本地覆盖」一行，可以随时确认。

> ⚠️ **不要把未确认的 beta 分支直接用于真机**。特殊机型（如 V63 或特殊底盘）的分支名与适用范围
> 必须由维护者确认，见 [`../06-常见问题FAQ/03-SDK-与版本.md`](../06-常见问题FAQ/03-SDK-与版本.md) 第 5 节。

## 四、卸载

### 4.1 只卸载 Python 包（保留 SDK 源码）

```bash
cd ~/letools_opensource
./scripts/sdk_tools/remove.sh
```

等价于：

```bash
python3 -m pip uninstall -y kuavo-humanoid-sdk
```

脚本在动手前会列出将要执行的操作并要求确认；自动化环境加 `--yes` 跳过。

### 4.2 连 SDK 源码一起删除

```bash
./scripts/sdk_tools/remove.sh --source     # 删源码；仓库数据保留，重装时不用重新下载
./scripts/sdk_tools/remove.sh --purge      # 彻底清除：源码 + 仓库数据 + submodule 登记
```

脚本内置了路径白名单：**只会删除项目内 `drivers/leju/kuavo_humanoid_sdk` 及其对应的仓库数据目录**，
解析出别的路径会直接拒绝执行。源码目录里有未提交的本地修改时，确认前会先列出来。

| 命令 | 卸 Python 包 | 删 SDK 源码 | 删仓库数据 | 重装时 |
|---|---|---|---|---|
| `./scripts/sdk_tools/remove.sh` | ✓ | ✗ | ✗ | 只重装 pip 包 |
| `./scripts/sdk_tools/remove.sh --source` | ✓ | ✓ | ✗ | 从本地仓库数据恢复源码 |
| `./scripts/sdk_tools/remove.sh --purge` | ✓ | ✓ | ✓ | 等同全新安装 |

### 4.3 关于「删子模块再重装」

**不要手动 `rm -rf drivers/leju/kuavo_humanoid_sdk` 当默认操作**。
正常升级 / 回退请直接跑 `./scripts/sdk_tools/install.sh`——它会自己检测并修复损坏的 submodule 元数据。
只有在**确认 submodule 损坏、没有本地修改或已备份**、且重跑安装脚本仍然失败时，才彻底清除后重装：

```bash
./scripts/sdk_tools/remove.sh --purge
./scripts/sdk_tools/install.sh
```

## 五、卸载之后

卸完 SDK 后，`adapters` 层的运行会失败（它内部要调 SDK）。要恢复：

```bash
cd ~/letools_opensource
./scripts/sdk_tools/install.sh
python3 -c 'from kuavo_humanoid_sdk import KuavoRobot; print("SDK Ready")'
```
