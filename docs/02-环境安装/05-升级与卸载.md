# 05 升级与卸载

[返回文档首页](../README.md) · [01-介绍](../01-介绍/) · [02-环境安装](../02-环境安装/)

> 本篇说明三件事：**怎么升级到新版本、怎么回退到锁定版本、怎么把 SDK 卸干净**。
> 首次安装见 [`03-安装步骤.md`](03-安装步骤.md)，装完的验证见 [`04-环境验证.md`](04-环境验证.md)。
> 文中 `scripts/`、`infrastructure/` 等相对路径一律相对 LeTools 仓库根目录，命令默认在仓库根目录执行。

**版本跟着锁文件走**：升级 = 拉新代码让 `sdk_version.env` 变新，再重跑安装脚本；
回退 = 把代码切回旧版本/旧 tag，同样重跑安装脚本。**不要手动 `git checkout` SDK 里的分支**。

## 一、两个脚本的分工

| 脚本 | 用途 | 从哪拿 SDK | 何时用 |
|---|---|---|---|
| `scripts/install_sdk.sh` | **安装 SDK 的统一入口** | 按 `sdk_version.env` 从远程仓库初始化 submodule 并 sparse-checkout | 首次安装、升级、回退后重装 |
| `scripts/remove_local_sdk.sh` | 卸载 | — | 清理环境、换版本前彻底清干净 |

`install_sdk.sh` 的顺序是：读锁文件 → **校验 branch/tag 配对** →
初始化 submodule（并自动修复损坏的 submodule 元数据）→ sparse-checkout 只取 `src/kuavo_humanoid_sdk/*`
→ 透传 tag 给 `setup_sdk.sh` 完成安装。

## 二、升级

### 2.1 升级 LeTools 本体（含 SDK）

```bash
cd ~/letools_opensource

# 1) 拉新代码；新版本的 sdk_version.env 会带来新的配套 SDK 版本
git pull

# 2) 看新的锁定版本是什么
cat scripts/kuavo_humanoid_sdk_tools/sdk_version.env

# 3) 先重编译 ROS 工作空间（消息包可能变了；SDK 安装时会从 devel 中取 kuavo_msgs / ocs2_msgs）
cd infrastructure/ros_packages
source /opt/ros/noetic/setup.bash
catkin build
source devel/setup.bash

# 4) 再按新锁重装 SDK
cd ~/letools_opensource
./scripts/install_sdk.sh        # 运行时间较长，耐心等待

# 5) 回归验证
cd ~/letools_opensource
bash scripts/check_environment.sh
python3 -c 'from kuavo_humanoid_sdk import KuavoRobot; print("SDK Ready")'
```

> ⚠️ **顺序不能反**：先编译消息包，再装 SDK。反过来时，SDK 会带上旧的消息定义，或因找不到消息包直接退出。
>
> ⚠️ **消息包变了必须重编译**。`kuavo_msgs` / `ocs2_msgs` 在多个仓库中有副本，
> **md5sum 不一致会导致话题订阅失败**，而这不会在 import 阶段报错。

### 2.2 只重装 SDK（LeTools 代码不变）

```bash
cd ~/letools_opensource
./scripts/install_sdk.sh
```

脚本自身是幂等的：submodule 已就绪就直接进入安装流程，损坏则先自动修复
（`git submodule deinit` + 清理残留）再重新初始化。

## 三、版本回退

### 3.1 回退到当前锁定的版本（最常见）

「装成了别的版本，想回到仓库配套的那一版」：

```bash
cd ~/letools_opensource

# 1) 确认目标版本
cat scripts/kuavo_humanoid_sdk_tools/sdk_version.env   # SDK_REPO_BRANCH / SDK_REPO_TAG

# 2) 确认没有把 sdk_config.sh 里的临时覆盖留着
grep -E 'SDK_REPO_BRANCH|SDK_REPO_TAG' scripts/kuavo_humanoid_sdk_tools/sdk_config.sh
#    两项都应为空 ""（空 = 使用 sdk_version.env 的配套版本）

# 3) 清掉 SDK 源码与已装包，再重装
./scripts/remove_local_sdk.sh --remove-source
./scripts/install_sdk.sh
```

### 3.2 回退到 LeTools 的旧版本

```bash
cd ~/letools_opensource
git log --oneline -- scripts/kuavo_humanoid_sdk_tools/sdk_version.env   # 找旧版本的锁定值
git checkout <旧版本 commit 或 tag>
git submodule update --init --force drivers/leju/kuavo_humanoid_sdk

# 先重编译 ROS 工作空间，再装 SDK（顺序同 2.1）
cd infrastructure/ros_packages && source /opt/ros/noetic/setup.bash && catkin build && source devel/setup.bash
cd ~/letools_opensource
./scripts/install_sdk.sh
```

回退后跑一遍 [`04-环境验证.md`](04-环境验证.md) 的验收清单。

### 3.3 临时切到其它 SDK 版本调试

**只改 `sdk_config.sh`，不要改 `sdk_version.env`**：前者被 `.gitignore` 忽略，后者随仓库发版。

```bash
cd ~/letools_opensource
cat scripts/kuavo_humanoid_sdk_tools/sdk_config.sh
```

```bash
# scripts/kuavo_humanoid_sdk_tools/sdk_config.sh
# 默认留空 = 使用 sdk_version.env 的配套版本
export SDK_REPO_BRANCH="dev"        # 临时调试用的分支
export SDK_REPO_TAG="1.4.4"         # 该分支上确实存在的 tag
```

两项**必须同时设置**，且 tag 必须属于该分支——`install_sdk.sh` 会用
`git merge-base --is-ancestor` 校验，不通过直接退出：

```text
❌ tag 1.4.4 不在分支 dev 上（或不是该分支的祖先）
```

调试完请**把两项改回空字符串**，否则后续升级会一直装着临时版本而不自知。

> ⚠️ **不要把未确认的 beta 分支直接用于真机**。特殊机型（如 V63 或特殊底盘）的分支名与适用范围
> 必须由维护者确认，见 [`../06-常见问题FAQ/03-SDK-与版本.md`](../06-常见问题FAQ/03-SDK-与版本.md) 第 5 节。

## 四、卸载

### 4.1 只卸载 Python 包（保留 SDK 源码）

```bash
cd ~/letools_opensource
./scripts/remove_local_sdk.sh
```

等价于：

```bash
python3 -m pip uninstall -y kuavo-humanoid-sdk
```

脚本在动手前会要求输入 `yes` 确认；自动化环境加 `--yes` 跳过。

### 4.2 连 SDK 源码一起删除

```bash
./scripts/remove_local_sdk.sh --remove-source
```

`--remove-source` 会 `rm -rf` 掉 `drivers/leju/kuavo_humanoid_sdk`。
脚本内置了路径白名单：**只会删除项目内 `drivers/leju/kuavo_humanoid_sdk` 这一个路径**，
解析出别的路径会直接拒绝执行（`拒绝删除未预期的路径`）。

| 命令 | 卸 Python 包 | 删 SDK 源码 | 确认提示 |
|---|---|---|---|
| `./scripts/remove_local_sdk.sh` | ✓ | ✗ | 需要输入 `yes` |
| `./scripts/remove_local_sdk.sh --remove-source` | ✓ | ✓ | 需要输入 `yes` |
| 加 `--yes` | ✓ | 同上 | 跳过 |

### 4.3 关于「删子模块再重装」

文档里常出现的这一步，**不要当默认操作**：

```bash
rm -rf drivers/leju/kuavo_humanoid_sdk
```

只有在**确认 submodule 损坏、没有本地修改、且已备份**时才清。
正常升级 / 回退请直接跑 `./scripts/install_sdk.sh`——它会自己检测并修复损坏的 submodule 元数据。

## 五、卸载之后

卸完 SDK 后，`adapters` 层的运行会失败（它内部要调 SDK）。要恢复：

```bash
cd ~/letools_opensource
./scripts/install_sdk.sh
python3 -c 'from kuavo_humanoid_sdk import KuavoRobot; print("SDK Ready")'
```
