## 一、仿真环境部署

### 1.1 环境部署

仿真需要两个独立项目配合：

```text
kuavo-ros-opensource：MuJoCo、底层控制器、ROS 基础环境
LeTools：SDK 适配、技能、行为树和上位机示例
```

目前支持的部署方式是：**宿主机为 Ubuntu 20.04，运行 LeTools；kuavo-ros-opensource、MuJoCo 和控制器运行在 Docker 容器中**。其他组合（例如宿主机不是 20.04、全部原生安装）未经验证，见 [`01-系统要求.md`](01-系统要求.md)。

| | 宿主机（Ubuntu 20.04） | Docker 容器 |
|---|---|---|
| 系统与 ROS | 安装 ROS Noetic | 镜像内置 ROS Noetic |
| 代码 | 克隆 LeTools 和 kuavo-ros-opensource（后者挂载进容器） | 宿主机的 kuavo-ros-opensource 挂载为 `/root/kuavo_ws` |
| 编译 | LeTools 的 catkin 工作空间（第三节） | kuavo-ros-opensource 的控制器（本节第 4 步） |
| 运行 | 行为树、SDK、TF 转发、示例脚本 | MuJoCo 仿真器、控制器 |
| 通信 | Docker 使用 host 网络，宿主机与容器连接同一个 ROS master | |

注意事项：

- 两个项目在宿主机上保持同级目录，**不要把 LeTools 克隆到** `kuavo-ros-opensource` **内部**——两个项目都包含 catkin 工作空间，嵌套后 catkin 可能向上找到错误的 `build`、`devel`、`.catkin_tools`；
- 同一个 catkin 工作空间不要交替在宿主机和容器中编译。catkin 产物记录绝对路径，例如 `/home/<用户名>/...` 与 `/root/...` 不可混用。

按以下顺序完成部署：

#### 第 1 步：准备宿主机

硬件方面的要求：

- **磁盘**：自检脚本以项目盘剩余 ≥ 10 GB 为阈值（不足报 `W012`），包含 Docker 镜像时需要更多空间；
- **内存**：内存不足时，编译进程可能被系统终止（OOM）；可用 `catkin build <包名> -p 1` 降低并发；
- **GPU**：可选。无 GPU 时可以完成代码开发、静态检查、单元测试和 dry-run，MuJoCo 可用 `docker/run.sh` 运行；仿真卡顿时改用 `docker/run_with_gpu.sh`（需要 NVIDIA GPU，见下文）。

具体场景能否在 MuJoCo 中运行，以场景目录内的 README 为准。

核对基础环境：

```bash
lsb_release -a
source /opt/ros/noetic/setup.bash
rosversion -d
python3 --version
git --version
catkin --version
docker --version
```

预期：Ubuntu 20.04、ROS 输出 `noetic`、Python 为 3.8 或更高。

安装常用依赖：

```bash
sudo apt update
sudo apt install -y python3-pip python3-rosdep python3-catkin-tools python3-empy python3-catkin-pkg python3-rospkg libgflags-dev unzip
python3 -m pip install --upgrade "numpy>=1.19.5,<1.27.0"
```

如果提示符含 `(base)`，先退出 Conda，避免 ROS Noetic 调用 Conda Python：

```bash
conda deactivate
which python3   # 推荐输出 /usr/bin/python3
```

**查看显卡（NVIDIA GPU 可选）**

只有使用 NVIDIA GPU 容器时才需要检查：

```bash
nvidia-smi
nvidia-ctk --version
docker info | grep -i runtime
```

若 Docker 的 Runtimes 已包含 `nvidia`，不需要重复安装或配置 NVIDIA Container Toolkit。
`nvidia-ctk runtime configure` 必须在宿主机执行，不是在容器内执行。普通仿真足够流畅时可以继续使用 `docker/run.sh`，不需要 GPU。

需要在容器中使用 NVIDIA GPU（如 `run_with_gpu.sh`）时，宿主机需安装 NVIDIA 驱动和 NVIDIA Container Toolkit。按官方顺序执行：添加软件源 → 安装 → 配置 Docker 运行时 → 重启 Docker。以下命令摘自 [NVIDIA 官方安装指南](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)，如有出入以官方文档为准：

```bash
# 1) 添加 NVIDIA Container Toolkit 软件源
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg \
  && curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
     sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
     sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

# 2) 安装
sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit

# 3) 配置 Docker 运行时并重启 Docker
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

安装后的验证方法见 [FAQ 01 安装与环境](../06-常见问题FAQ/01-安装与环境.md) 中 Docker 与 GPU 一节。

#### 第 2 步：获取 kuavo-ros-opensource

版本以 LeTools 的 `scripts/kuavo_humanoid_sdk_tools/sdk_version.env` 中的 `SDK_REPO_TAG` 为准（当前为 `1.4.5`）。`1.4.5` 是 **Tag**，不是分支。建议单独克隆，避免复用其他版本的编译缓存：

```bash
cd "$HOME"
git clone --branch 1.4.5 --single-branch --recurse-submodules https://gitcode.com/OpenLET/kuavo-ros-opensource.git kuavo-ros-opensource-1.4.5
cd "$HOME/kuavo-ros-opensource-1.4.5"
git describe --tags --exact-match   # 应输出 1.4.5
git rev-parse --short HEAD
```

> 代码 Tag、Docker 镜像和 OpenVINO 必须配套，否则控制器启动时会出现 `libopenvino.so.2520` 找不到等错误，判断方法见 [FAQ 01 安装与环境](../06-常见问题FAQ/01-安装与环境.md) 的 2.3。

#### 第 3 步：准备 Docker 镜像并进入容器

镜像可以自行查看网上相关配置用 `./docker/Dockerfile` 构建，或下载已经编译好的镜像：

```bash
wget https://kuavo.lejurobot.com/kuavo_research_editiion/docker_images/kuavo_opensource_mpc_wbc_img_v1.3.0.tar.gz
sudo docker load -i kuavo_opensource_mpc_wbc_img_v1.3.0.tar.gz
```

💡 （推荐）进入 **[kuavo-ros-opensource](https://gitcode.com/OpenLET/kuavo-ros-opensource)** 目录执行 `./docker/run.sh`
进入容器：

```bash
cd "$HOME/kuavo-ros-opensource-1.4.5"
chmod +x docker/run.sh
./docker/run.sh
```

宿主机仓库通常会挂载为：

```text
/home/<用户名>/kuavo-ros-opensource-1.4.5 → /root/kuavo_ws
```

因此容器内显示 `/root/kuavo_ws` 是正常的；此时**不要再执行** `cd kuavo-ros-opensource`。

> 💡 **提示**
>
> - 容器镜像内部默认使用 zsh；
> - `.sh` 类型文件不能运行记得给权限，`chmod +x ./docker/run.sh`；
> - 若启动后仿真卡顿可以在同级目录运行 `./docker/run_with_gpu.sh`。

#### 第 4 步：在容器内编译控制器

先确认容器内工作空间：

```bash
pwd
git describe --tags --exact-match
ls
```

然后编译：

```bash
cd /root/kuavo_ws
source /opt/ros/noetic/setup.zsh
source installed/setup.zsh
catkin config -DCMAKE_ASM_COMPILER=/usr/bin/as -DCMAKE_BUILD_TYPE=Release
catkin build humanoid_controllers -p 1
```

`-p 1` 让 catkin 一次只调度一个包，可降低首次构建时「依赖正在安装、下游已经开始链接」的竞态风险。

**OpenVINO 检查：按依赖顺序补编译**

```bash
cd /root/kuavo_ws
source /opt/ros/noetic/setup.zsh
source installed/setup.zsh
catkin build kuavo_assets -p 1
source devel/setup.zsh
catkin build humanoid_interface_ros -p 1
```

> `-DCMAKE_ASM_COMPILER=/usr/bin/as` 是配置 ccache 的必要操作，否则可能出现找不到编译器的情况。

#### 第 5 步：在宿主机部署 LeTools

按本文[第三节](#三letools-工具链部署两条路径共用)在宿主机部署 LeTools 工具链（Python 依赖、ROS 工作空间、SDK），完成后进入 1.2 做仿真验证。

### 1.2 MuJoCo 仿真验证

在 Docker 容器中设置与目标模型匹配的版本，再启动仿真：

```bash
cd /root/kuavo_ws
export ROBOT_VERSION=62
echo "$ROBOT_VERSION"
source devel/setup.zsh
roslaunch humanoid_controllers load_kuavo_mujoco_sim_wheel.launch   # 轮臂机器人请使用
roslaunch humanoid_controllers load_kuavo_mujoco_sim.launch         # 启动控制器、mpc、wbc、mujoco 仿真器
```

`62` 表示机器人配置版本 62，只是常用示例，**不是 SDK 版本**，必须按目标机器人选择。

若当前容器使用 zsh，可写入 `~/.zshrc`：

```bash
grep -qxF 'export ROBOT_VERSION=62' ~/.zshrc || echo 'export ROBOT_VERSION=62' >> ~/.zshrc
```

容器重建后该文件可能丢失；长期使用可在 Docker 启动参数中加入 `-e ROBOT_VERSION=62`。

Oh My Zsh 访问 GitHub 更新失败与 ROS、MuJoCo 无关，更新询问可直接选择 `n`。

**从宿主机运行 LeTools 示例**

保持容器中的 MuJoCo 终端运行，在宿主机新开终端（前置条件：LeTools 工具链已按本文第三节部署完毕）：

```bash
conda deactivate 2>/dev/null || true
cd "$HOME/letools_opensource"
source /opt/ros/noetic/setup.bash
source infrastructure/ros_packages/devel/setup.bash
export PYTHONPATH="$(pwd):${PYTHONPATH}"
rosnode list
rosservice list | grep mobile_manipulator   # 应能看到 /mobile_manipulator_mpc_control 等服务
python3 apps/test_kuavo_5w_sdk_adapter/sdk/01_head/test_head_control.py
```

运行后在 MuJoCo 仿真中应能看到机器人头部按照预设的动作活动。

若宿主机看不到容器中的 ROS 节点，检查 Docker 是否使用 host 网络，并检查双方的 `ROS_MASTER_URI`。

**能力边界**

| 阶段 | 可以验证 | 不能证明 |
|---|---|---|
| dry-run | Python、JSON、节点、子树、board | ROS 服务和运动 |
| MuJoCo | ROS/SDK 链路、时序、数据流、部分运动 | 真实安全、负载、视觉和抓取精度 |
| 真机 | 动力学、负载、精度、安全和稳定性 | — |

`jibot_nav_v1` 等真机场景依赖 JiBot 调度服务，不能直接在 MuJoCo 运行；仿真请使用对应的仿真版场景（如 `jibot_nav_v1_sim`）。fake tag 只能验证后续流程，
不能证明真实视觉通过。

## 二、真机部署

> 本段基于「从仿真验证完之后往真机部署」的经验汇总，是一条标准化流程。

### 2.1 下位机部署与跑通

**部署**

下位机运控 `kuavo-ros-opensource` 的版本必须与 LeTools 配套，以 LeTools 仓库中 `scripts/kuavo_humanoid_sdk_tools/sdk_version.env` 的 `SDK_REPO_TAG` 为准（当前为 `1.4.5`）：

```bash
# 查看配套版本（在 LeTools 仓库中执行）
cat scripts/kuavo_humanoid_sdk_tools/sdk_version.env

# 在下位机克隆对应 tag
git clone -b 1.4.5 https://gitcode.com/OpenLET/kuavo-ros-opensource.git

# 编译运行
cd kuavo-ros-opensource   # 仓库目录
catkin config -DCMAKE_ASM_COMPILER=/usr/bin/as -DCMAKE_BUILD_TYPE=Release  # Important!
source installed/setup.bash   # 加载一些已经安装的 ROS 包依赖环境，包括硬件包等
catkin build humanoid_controllers
```

> 💡 **提示**：5-10 分钟即可完成编译。

**运行**

```bash
cd kuavo-ros-opensource
sudo su
source devel/setup.bash
roslaunch humanoid_controllers load_kuavo_real_wheel.launch
# 运行后按照提示日志按 "o"，一直后台挂着即可
```

**跑通**

下位机不需要安装 SDK。用 `kuavo-ros-opensource` 自带的话题版示例（`src/demo/test_kuavo_wheel_real/`，只依赖 ROS）验证控制器，以手臂关节示例为例：

> ⚠️ 该脚本会让真机手臂运动，运行前按 [真机运行前安全检查](../04-简单案例运行/02-执行命令.md#真机运行前安全检查) 逐项确认。

```bash
# 新开一个终端，运行脚本（控制器保持运行）
cd kuavo-ros-opensource
sudo su
source devel/setup.bash
cd src/demo/test_kuavo_wheel_real/
python3 cmd_arm_joint_test.py
```

> 💡 **提示**：观察机器人手臂运行正常即可。同目录下还有底盘（`cmd_pos_base_test.py` 等）、躯干、腿部的话题版示例。
> LeTools 运行时所需的 TF 转发服务在上位机启动，见 [3.6](#36-启动-kuavo_tf2_web_republisher-服务)。

### 2.2 上位机部署跑通

上位机 SSH 进去后参照仿真环境部署，跑通即可。

如果上位机主目录所在磁盘空间较小，建议部署到空间较大的数据盘。

## 三、LeTools 工具链部署（两条路径共用）

无论走仿真还是真机，宿主机上的 LeTools 工具链都按本节部署。

### 3.1 前置准备

确保你的系统已安装 Python 3.8+ 和 ROS Noetic，并且 `numpy` 版本满足要求：

```bash
pip3 install --upgrade "numpy>=1.19.5,<1.27.0"
```

### 3.2 获取工具链项目

从开源仓库获取工具链项目（`letools_opensource`）：

```bash
cd ~
git clone https://gitcode.com/OpenLET/letools_opensource.git
cd letools_opensource
```

安装 LeTools 自有 Python 依赖（`colorlog`、`py_trees`、`scipy>=1.4`，说明见 [`02-依赖版本清单.md`](02-依赖版本清单.md)）：

```bash
pip3 install -r requirements.txt
```

> Ubuntu 20.04 自带的 `python3-scipy` 为 1.3.3，低于 `scipy>=1.4` 的要求，跳过这一步会导致位姿换算在运行期报错。

### 3.3 编译 ROS 工作空间

按以下顺序配置后再编译。extend 和 skiplist 都要在 `catkin build` **之前**设置，否则需要清理后重新编译。

**第 1 步：加载 ROS 环境**

```bash
source /opt/ros/noetic/setup.bash
cd ~/letools_opensource/infrastructure/ros_packages
```

**第 2 步（仿真部署时）：继承 kuavo-ros-opensource 的安装环境**

让 LeTools 工作空间明确继承按 1.1 第 2 步克隆的 `kuavo-ros-opensource` 的安装环境：

```bash
source "$HOME/kuavo-ros-opensource-1.4.5/installed/setup.bash"
catkin config --extend "$HOME/kuavo-ros-opensource-1.4.5/installed" -DCMAKE_ASM_COMPILER=/usr/bin/as -DCMAKE_BUILD_TYPE=Release
```

**第 3 步（可选）：暂不需要视觉时跳过视觉相关包**

视觉模块编译失败、或只做 SDK / 行为树 / 无视觉仿真时，先设置 skiplist：

```bash
catkin config --skiplist detection_yolo_v8 ar_control kuavo_vision_object kuavo_yolo_point2d yolo_box_object_detection yolo_button_object_detection yolo_valve_object_detection orbbec_camera realsense2_camera kuavo_camera
```

> 💡 上面写成**单行命令**是刻意的：多行命令里反斜杠后一旦插入空行，会被 shell 拆开并报 `command not found`。
> ⚠️ 不要跳过 `kuavo_tf2_web_republisher`：它提供 SDK 初始化所需的 TF 转发服务。

**第 4 步：编译并验证**

```bash
catkin build
source devel/setup.bash
python3 -c 'import kuavo_msgs; import ocs2_msgs; print("ROS messages ready")'
```

**常见问题**

- 出现 `gflags/gflags.h: 没有那个文件或目录`：执行 `sudo apt install -y libgflags-dev` 后重新 `catkin build`。
- 修改 extend 或 skiplist 后，catkin 警告缓存中的 `CMAKE_PREFIX_PATH` 与新路径不同：先用 `pwd` 确认当前在 `infrastructure/ros_packages`，再执行 `catkin clean -y` 后重新编译。

### 3.4 安装 SDK

**当前配套版本**

仓库文件 `scripts/kuavo_humanoid_sdk_tools/sdk_version.env` 记录当前 LeTools 配套的 kuavo-ros-opensource 分支与 tag：

```bash
SDK_REPO_BRANCH="master"
SDK_REPO_TAG="1.4.5"
```

SDK 安装的唯一入口是 `scripts/install_sdk.sh`，相关配置都在 `scripts/kuavo_humanoid_sdk_tools/` 下：

| 文件 | 作用 | 是否需要修改 |
|---|---|---|
| `sdk_version.env` | 版本锁定清单，记录配套的分支与 tag，随 LeTools 发版更新 | 不要修改 |
| `sdk_config.sh.template` | 本地配置模板 | 不要修改 |
| `sdk_config.sh` | 本地配置；首次运行 `install_sdk.sh` 时由模板自动生成，已被 `.gitignore` 忽略 | 按需修改 |

`sdk_config.sh` 中常用的配置项：

- `SDK_EXTRAS`：可选依赖，取值 `""`（默认，不装）、`audio`（语音）、`vision`（视觉）、`full`（全部）；
- `SDK_REPO_BRANCH` / `SDK_REPO_TAG`：默认留空，即使用 `sdk_version.env` 的配套版本；只在临时调试其他版本时**同时**填写两项，调试结束后清空。

普通用户不需要修改版本相关配置，直接运行安装脚本即可。

**一键安装（推荐）**

新开一个终端，在项目根目录运行以下命令，脚本将自动完成 Submodule 初始化、分支切换、配置生成及 SDK 安装：

```bash
cd ~/letools_opensource
chmod +x scripts/install_sdk.sh
./scripts/install_sdk.sh   # 需要访问 SDK 远端仓库，耗时较长
```

脚本检测到子模块元数据损坏时会自动清理并重新初始化。仅当脚本仍因子模块残留失败时，才手动清理后重跑：

```bash
# ⚠️ 仅在确认子模块损坏、其中没有需要保留的本地修改（或已备份）时执行
rm -rf drivers/leju/kuavo_humanoid_sdk
./scripts/install_sdk.sh
```

### 3.5 验证安装

运行以下 Python 命令，若输出 `SDK Ready!` 则代表安装成功：

```bash
python3 -c 'from kuavo_humanoid_sdk import KuavoRobot; print("SDK Ready!")'
```

若出现 `ModuleNotFoundError`，先检查安装脚本是否成功、Python 解释器是否一致，再查阅
[`../06-常见问题FAQ/03-SDK-与版本.md`](../06-常见问题FAQ/03-SDK-与版本.md)。

> 💡 **提示**：原文档路径为 `/kuavo/docs/guides/SDK_Integration_Guide.md`。

### 3.6 启动 kuavo_tf2_web_republisher 服务

```bash
# 加载 3.3 中编译好的工作空间
cd ~/letools_opensource/infrastructure/ros_packages
source devel/setup.bash
```

## 附录 B：常见错误速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `cd kuavo-ros-opensource: no such file` | 容器内仓库名是挂载点 `/root/kuavo_ws` | 留在 `/root/kuavo_ws` |
| `-v: command not found` | `-v` 是 `docker run` 参数，不是独立命令 | 写入 Docker 启动参数 |
| `--workspace: command not found` | 反斜杠后插入空行，命令被拆开 | 使用本文单行命令 |
| catkin 显示错误 Workspace | 两个 catkin 工作空间嵌套或缓存路径错误 | 分离仓库并清理对应工作空间缓存 |
| Resultspace path 不存在 | `.catkin_tools` 保留了旧绝对路径 | 修正 `extend_path` 并 `catkin clean -y` |
| 找不到 `empy` | Conda Python 覆盖 ROS 系统 Python | 退出 Conda 并安装 `python3-empy` |
| 找不到 `gflags/gflags.h` | 宿主机缺少开发包 | 安装 `libgflags-dev` |
| `libopenvino.so.2520` 不存在 | 控制器与镜像 OpenVINO 版本不一致 | 使用配套镜像或一致环境重编译 |
| `libkuavo_assets.so` 不存在 | 首次并行构建发生依赖竞态 | 按「OpenVINO 检查」串行补编译 |
| Oh My Zsh 更新失败 | 容器无法连接 GitHub | 选择 `n`，不影响仿真 |
| `cd` 提示目录不存在 | 仓库不一定叫 `letools_opensource` | 用 `pwd` 和 `ls` 确认实际仓库路径 |
| `ModuleNotFoundError` | SDK 安装、Python 解释器或 `PYTHONPATH` 不一致 | 见 3.5 与 [`../06-常见问题FAQ/03-SDK-与版本.md`](../06-常见问题FAQ/03-SDK-与版本.md) |
| dry-run 提示主树不存在 | `--scenario` 路径及当前工作目录不对 | 从仓库根目录执行并核对场景名 |
| 子树 `KeyError` | 主树引用名与 `py_tree_child.json` 的 key 不一致 | 核对两处命名 |
| board 字段缺失 | `board.json` 与节点输入不同步 | 同步黑板键名与节点参数 |
| ROS master 连接失败 | 现场 ROS 网络变量和下位机状态问题 | 检查 `ROS_MASTER_URI` 与下位机状态 |
