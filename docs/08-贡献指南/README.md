# 08 贡献指南

本章写给要把改动合回 LeTools 仓库的人：从切分支到合并请求被合入，每一步读哪篇、做什么、拿到什么结果才算过关。只在本地使用 LeTools 的读者不需要这一章，按[文档首页](../README.md)的路线 A、B 选篇即可。

## 七步贡献流程

| 步 | 做什么 | 读哪篇 |
|---|---|---|
| 1 | 读环境与项目：跑通一次 dry-run，弄清代码分层与目录职责 | [文档首页](../README.md) 路线 A；[目录结构总览](../01-介绍/06-目录结构总览.md) |
| 2 | 认领或沟通：先在 `docs/` 里搜同主题的现成页面，有就扩写、不新建平行页；提改动或反馈时附上对应单号，确实没有单号的写明来源 | [04 文档贡献规范](./04-文档贡献规范.md) 第一、二节；[02 提交信息与合并请求](./02-提交信息与合并请求.md) 第六节 |
| 3 | 开分支：从 `dev` 最新提交切出，按三段式命名 | [01 开发与分支流程](./01-开发与分支流程.md) 第二至四节 |
| 4 | 提交：按格式写 commit 标题，一个 commit 只做一件事 | [02 提交信息与合并请求](./02-提交信息与合并请求.md) 第一至四节 |
| 5 | 自检：跑推送前门禁与文档守卫，分清既有失败和本次新增的失败 | [03 测试与质量检查](./03-测试与质量检查.md) |
| 6 | 开合并请求：填全模板字段，判定风险等级，写清实际跑过的验证 | [02 提交信息与合并请求](./02-提交信息与合并请求.md) 第六至九节 |
| 7 | 评审与合并：按意见返修，合并用 squash，出问题用 revert 回退 | [02 提交信息与合并请求](./02-提交信息与合并请求.md) 第十节；[01 开发与分支流程](./01-开发与分支流程.md) 第六节 |

## 公开边界

对外用户需要的内容写进 `docs/`，随开源产物一起发布；只对内部人员有意义的流程、权限与基础设施说明不写进这里，公开文档也不链接它们。判断标准见 [04 文档贡献规范](./04-文档贡献规范.md) 第一、二节。
