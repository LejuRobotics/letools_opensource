# 01 最小可运行示例

[返回文档首页](../README.md) · [04-简单案例运行](../04-简单案例运行/) · [03-接口详细文档](../03-接口详细文档/)

**难度**：⭐

**适合读者**：第一次接触 LeTools 行为树、只想先确认「这套东西在我机器上跑得起来」的人。

**前置知识**：会开终端、会 `cd`。不需要懂 ROS，也不需要连机器人。

**学习目标**：用最短路径跑通一棵行为树，看到「加载成功 + 一次 tick 成功」的输出。

---

## 一、这篇只做一件事

用仓库自带的冒烟场景 `studio_smoke_v1`，在**不连机器人、不启动 ROS** 的前提下，把一棵 5 个节点的行为树加载起来并 tick 一次。

这条命令不产生任何真实运动，它验证的是：

- Python 依赖能 import（`py_trees` 等）；
- 三个 JSON 文件语法正确、字段能被解析；
- 节点类名、子树键名都能在仓库里找到；
- 行为树能构造出一棵完整的树并 tick。

> 真实硬件行为、ROS 服务、动力学都不在这条命令的覆盖范围内。它们要等到 [06-头部顺序动作-instructional_case_01](06-头部顺序动作-instructional_case_01.md) 及之后的场景篇。

---

## 二、三条命令

```bash
# 1. 进入仓库根目录
cd /path/to/LeTools

# 2. 让 Python 找得到包（core / adapters / skills / orchestration）
export PYTHONPATH=$(pwd):$PYTHONPATH

# 3. 干跑：加载 studio_smoke_v1，只 tick 一拍
python3 apps/test_upper_init/run_behavior_tree_json.py \
  --scenario orchestration/scenarios/studio_smoke_v1 \
  --dry-run --tick-once
```

- `--scenario <目录>`：指定场景目录，启动器会自动取该目录下的 `py_tree.json`（主树）、`py_tree_child.json`（子树库）、`board.json`（黑板）。
- `--dry-run`：设 `STUDIO_DRY_RUN=1`，**不初始化 ROS，也不创建 `IHardware`**；运动节点与 `WaitForEnter` 这类阻塞节点直接返回 `SUCCESS`。
- `--tick-once`：与 `--dry-run` 合用，只执行一拍。

---

## 三、预期输出

命令正常时，终端末尾应当出现（截取关键行）：

```text
[apps] 子树集合已加载：.../studio_smoke_v1/py_tree_child.json (count=0)
[apps][dry-run] 已加载树，根节点: studio_smoke_seq
[apps][dry-run] tick 后根状态: Status.SUCCESS
```

以 `tick 后根状态: Status.SUCCESS` 为成功判据。

> `studio_smoke_v1` 的 `py_tree_child.json` 里没有子树，所以 `count=0` 是正常的。
> dry-run 下退出码为 0 只代表树加载成功，不反映 tick 结果；判据的完整说明见 [04-预期输出](04-预期输出.md)。

---

## 四、这棵树长什么样

`studio_smoke_v1` 的主树是根 `Sequence` 下挂 4 个动作节点（连根共 5 个节点）：

```text
Sequence(studio_smoke_seq)
├── WaitForEnter        wait_enter
├── ChassisShortMove    chassis_short     vx=0.3 m/s, 3.0 s
├── LegShortMove        leg_short         [14.90, -32.01, 18.03, 30.0] °
└── MoveArmBaseJointTrajectories  arm_smoke   use_board_trajectory=true
```

干跑时这些运动节点都不真做动作，只是逐个返回 `SUCCESS`，所以一次 tick 就能让根节点走到 `SUCCESS`。

## 五、跑不通怎么办

| 现象 | 原因 | 处置 |
|------|------|------|
| `ModuleNotFoundError: No module named 'py_trees'` | 缺依赖 | 见 [02-环境安装/02-依赖版本清单](../02-环境安装/02-依赖版本清单.md) |
| `ModuleNotFoundError: No module named 'core'` / `'orchestration'` | 没设 `PYTHONPATH` | 回到第 2 步执行 `export PYTHONPATH=$(pwd):$PYTHONPATH` |
| `RuntimeError: 主树 py_tree.json 不存在` | 场景路径写错 | 核对 `orchestration/scenarios/<场景>/` 是否真实存在 |
| `ModuleNotFoundError: No module named 'kuavo_humanoid_sdk'` | 该场景的节点依赖 vendored SDK，本机未装 | 换 `studio_smoke_v1` 这类不依赖 SDK 的场景先跑通，再按 [02-环境安装](../02-环境安装/) 装 SDK |

逐条的错误对照与更多情况见 [05-常见错误](05-常见错误.md)。
