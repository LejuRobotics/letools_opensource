# 05 常见错误

[返回文档首页](../README.md) · [04-简单案例运行](../04-简单案例运行/) · [03-接口详细文档](../03-接口详细文档/)

**难度**：⭐

**适合读者**：命令报错了、想知道「先看哪一行、再改哪个文件」的人。

**学习目标**：建立一套固定的排错顺序，能自己把大多数报错定位到「环境 / 路径 / JSON / 节点 / 硬件」中的一类。

> 本篇讲**教学性的排错顺序**；按问题域分篇的排障清单（含运行期、仿真、性能等）见
> [06-常见问题FAQ/04-行为树与场景运行](../06-常见问题FAQ/04-行为树与场景运行.md)。两篇不重复。

## 一、先建立排错顺序

拿到一段报错，按这个顺序切：

1. **看退出码**（`echo $?`）：仿真 / 真机运行时 `0` 成功、`1` 树失败、`2` 未达终态；dry-run 时非 0 表示加载失败，加载成功后总是 `0`，tick 结果要看 `tick 后根状态:` 一行。
2. **看最后一行**：那是异常类型（`ModuleNotFoundError` / `KeyError` / `RuntimeError` / `FileNotFoundError`…）。
3. **往上找第一个 LeTools 文件**：traceback 里第一条路径在 `LeTools/` 内的帧，就是**你该改的地方**，上面的帧多半是库内部。
4. **归类**：环境、路径、JSON 结构、节点名、硬件配置——五类之一。

---

## 二、环境类

### `ModuleNotFoundError: No module named 'py_trees'`

- **原因**：依赖没装。
- **处置**：按 [02-环境安装/02-依赖版本清单](../02-环境安装/02-依赖版本清单.md) 装依赖（`py_trees` 版本被锁）。

### `ModuleNotFoundError: No module named 'core'` / `'orchestration'` / `'skills'`

- **原因**：`PYTHONPATH` 没包含仓库根。
- **处置**：

  ```bash
  cd /path/to/LeTools
  export PYTHONPATH=$(pwd):$PYTHONPATH
  ```

### `ModuleNotFoundError: No module named 'kuavo_humanoid_sdk'`

- **原因**：该场景的某个节点依赖 vendored SDK，本机未安装（SDK 是 submodule）。
- **处置**：按 [02-环境安装](../02-环境安装/) 装 SDK。**快速排查用**：这是**场景相关**的——已实测 `studio_smoke_v1`、`jibot_nav_v1_sim`、`refactored_sdk_atomic_v1` 三个场景在本机干跑能到 `SUCCESS`；`refactored_sdk_single_tag_pick_v0` 会因 `node_tag_to_arm_goal.py` → `utils/keypoints.py` import SDK 而失败。

### `No module named 'rospy'`

- **原因**：在非 ROS 环境里跑了不带 `--dry-run` 的命令。
- **处置**：要么加 `--dry-run` 做离线校验，要么先 `source /opt/ros/noetic/setup.bash` 并起 ROS。

## 三、路径类

### `RuntimeError: 主树 py_tree.json 不存在: <路径>`

- **原因**：`--scenario` 目录名写错，或 `--tree` 指到了不存在的文件。
- **处置**：`ls orchestration/scenarios/` 核对目录名，注意场景 id 与篇名里的 id 可能不同（篇名是 `NN-中文名-场景id`，`--scenario` 只认**场景 id 目录**）。

### `KeyError: 'xxx.json'`

- **原因**：主树里写了 `"name": "xxx.json"`，但该键不在 `py_tree_child.json` 里。
- **处置**：核对子树键名——**必须逐字一致**（含 `.json` 后缀）。工厂只从 `py_tree_child.json` 取子树，主树与子树的 `name` 一字之差即报错。

### 三个 JSON 不在同一个场景目录

- **现象**：主树能找到，但 `board.json` 或 `py_tree_child.json` 没被加载（`count=0` 却应该非 0）。
- **处置**：`--scenario` 只自动取**同一目录**下的三件套；跨目录要显式 `--tree` / `--subtrees` / `--board`。

## 四、JSON 结构类

| 报错/现象 | 原因 | 处置 |
|-----------|------|------|
| `json.decoder.JSONDecodeError` | JSON 语法错（多了尾逗号、引号没闭合） | `python3 -m json.tool <文件>` 定位行列 |
| 参数全部回退到默认值 | `params` 里 `value` 的 `data_type` 与内容不符 | 核对 `data_type`：`float` 就写数字、`string` 才写字符串 |
| `READ_BOARD` 读不到 | `board.json` 键名拼错 | 键名必须与节点声明的 `default_key` / `board_key` 一致，**拼错不报错** |
| 子树引用无反应 | 主树 `name` 结尾漏了 `.json` | 子树的 `name` **必须以 `.json` 结尾且完全等于键名** |
| 复合节点行为异常 | `params.memory` 没设或写错 | `Sequence`/`Selector` 常需 `memory=true`；`Parallel` 要有 `policy`（如 `success_on_all` / `success_on_one`） |

排查 JSON 结构最省事的办法：

```bash
python3 -m json.tool orchestration/scenarios/<场景>/py_tree.json        >/dev/null
python3 -m json.tool orchestration/scenarios/<场景>/py_tree_child.json  >/dev/null
python3 -m json.tool orchestration/scenarios/<场景>/board.json          >/dev/null
```

## 五、节点类名类

### 找不到节点类

- **原因**：`name` 写了 Python 类名，但 `orchestration/nodes/` 下没有该类（新旧两套节点名混用最常见，如把 `MultiTimedCommandMove` 写成 `MultiTimedCmdMove`）。
- **处置**：先确认类是否存在于 `orchestration/nodes/`（含子目录 `grasp_mtbf/` 等）；类名**大小写敏感**。

### 节点构造出来但行为不对

- **原因**：同名节点在两个 `tree_type` 下语义不同（例如 SDK 直调节点与场景专用节点）。
- **处置**：以场景 `readme.md` / 本篇的节点表为准，别照抄别的场景的参数名。

## 六、硬件配置类

| 现象 | 原因 | 处置 |
|------|------|------|
| 相机初始化失败 | 相机配置与硬件不符，或没装相机 | 在 `hardware_config.json` 置 `skip_camera: true` |
| 手臂 SDK 节点失败 | `sdk_managers_whitelist` 没包含 `arm` | 补进白名单（如 `["timed","arm","low"]`） |
| 找不到硬件 / 节点失败 | `skip_end_effector` / `skip_state_manager` 跳过了必需项 | 取消对应 `skip_*` |
| 找不到 `hardware_config.json` 也不报错 | **该场景本来就没有这个文件** | 正常现象；需要覆盖时用 `--hardware-config <文件>` 显式传（见 [03](03-行为树最小示例.md)） |

---

## 七、运行期类

| 现象 | 可能原因 | 处置 |
|------|----------|------|
| 节点卡住不返回 | 等 ROS 服务/事件超时设置过大，或对端没起 | 先确认对端服务在跑；适当调小 `*_timeout` |
| 超时 `FAILURE` | `*_timeout` 太小 | 适当调大；各节点超时参数的单位（秒 / 毫秒）以该节点的参数说明为准 |
| 头部动作「假成功」 | SDK 未初始化：打 ERROR 但返回 `True` | grep 日志里有没有 `SDK 未初始化，请先调用 initialize()` |
| 走位「报告完成」但没到位 | 部分底盘控制按预计时间盲等，不校验真实到位 | 仿真里用肉眼看 MuJoCo 窗口，别只看日志 |
