## 1. 问题：单场景 dry-run 就失败

**原因**：场景路径错误、依赖的 Python 模块未安装，或主树、子树、节点类无法加载。

**判断命令**

```bash
cd ~/letools_opensource
python3 apps/test_upper_init/run_behavior_tree_json.py \
  --scenario orchestration/scenarios/studio_smoke_v1 \
  --dry-run --tick-once
```

**解决方案**：核对场景目录名与实际路径一致；从 traceback 最后一行确认异常类型，再向上找第一个 LeTools 文件；确认 `adapters` / `skills` / `orchestration` 已在 `PYTHONPATH` 中。

**成功标准**：输出 `tick 后根状态: Status.SUCCESS`，主树、子树和节点类能够正常加载。

## 2. 问题：节点类、子树或 board 引用失败

**原因**：Python 类名大小写错误、子树键名拼错、`READ_BOARD` 的 `board_key` 不存在，或三个 JSON 不在同一场景目录。

**判断命令**

```bash
python3 -m json.tool orchestration/scenarios/<场景>/py_tree.json >/dev/null
python3 -m json.tool orchestration/scenarios/<场景>/py_tree_child.json >/dev/null
python3 -m json.tool orchestration/scenarios/<场景>/board.json >/dev/null
```

**解决方案**：核对 Python 类名大小写、子树键名、`READ_BOARD` 的 `board_key`，以及三个 JSON 是否在同一场景目录。

**成功标准**：三条 `json.tool` 均无语法错误；dry-run 能加载全部子树与节点类。

> 场景 JSON 的字段级说明（`py_tree.json` / `board.json` / `hardware_config.json` / `config/*.yaml`）见 [04-简单案例运行](../04-简单案例运行/)。

## 3. 问题：dry-run 通过但 MuJoCo 失败

**原因**：dry-run 不验证 ROS 服务、动态库、模型、控制器、运动结果或安全边界；这些环节在仿真中才会暴露。

**解决方案**：dry-run 不验证 ROS 服务、动态库、模型、控制器、运动结果或安全边界。继续检查：

```bash
rosnode list
rosservice list
rostopic hz /clock
grep -R "ERROR\|FATAL" ~/.ros/log/latest/ | head -50
```

再查看场景目录中的 README，确认该场景是否声明支持 MuJoCo。

**成功标准**：`rosnode list` 与 `rosservice list` 中出现该场景依赖的节点与服务，`/clock` 稳定。

**日志位置**：`~/.ros/log/latest/`，先看第一个 `ERROR/FATAL`。

## 4. 问题：JiBot 场景不能直接仿真

**原因**：`jibot_nav_v1` 依赖 JiBot/Jarvis 调度服务，普通 MuJoCo 环境不提供该服务。

**解决方案**：应选择不依赖 JiBot 的场景，或按仿真环境已有的底盘节点完成适配；不能把 dry-run 通过视为调度服务已经可用。

**成功标准**：选择不依赖 JiBot 的场景后 MuJoCo 能跑通；或仿真环境已提供等效的底盘调度节点。

---

## 5. 问题：嘉腾底盘不动，随后提示仍有任务执行

**原因**：`move_base` 前 `/enable_vel_control` 仍为 `true`，与任务模式冲突。

**判断命令**

```bash
rosservice list | grep enable_vel_control
rosservice call /enable_vel_control "data: false"
```

**解决方案**：重新发送一次任务并检查到达状态。

**成功标准**：底盘按任务移动，任务结束后不再提示仍有任务执行。

**详细说明**：完整说明见[嘉腾底盘控制文档](../../apps/jiateng_adapter/嘉腾底盘控制使用说明.md)。
