# 06 性能、稳定性与真机安全

[返回文档首页](../README.md) · [02-环境安装](../02-环境安装/) · [05-进阶开发指南](../05-进阶开发指南/)

> 本篇包括两类问题：
> 1–3 条是运行期「卡顿 / 变慢 / 时间不对」类问题；
> 4–6 条是真机安全相关问题：关节保护、停止入口和安全参数。
>
> 涉及真机运动、安全参数或急停时，如果现象无法解释，应停止尝试并联系维护者，
> 不要扩大阈值或无限重试绕过故障。

---

## 1. 问题：MuJoCo 卡顿

**原因**：CPU/内存/磁盘耗尽；仿真时钟 `/clock` 不稳；控制器反复重启；GPU 容器未获得 GPU；或同时运行视觉、录包与多个仿真实例。

**判断命令**

```bash
top
free -h
df -h
nvidia-smi
rostopic hz /clock
docker stats
```

**解决方案**：依次确认 CPU/内存/磁盘是否耗尽、`/clock` 是否稳定、控制器是否重启、GPU 容器是否获得 GPU，以及是否同时运行视觉、录包或多个仿真实例。

**成功标准**：`/clock` 频率稳定，`docker stats` 中仿真容器 CPU/内存无持续打满，`top` 中无异常高占用进程。

**相关**：GPU 是否已配置见 [01 安装与环境](01-安装与环境.md)。

## 2. 问题：手臂轨迹很慢或多次调用后越来越慢

**原因**：上层下发频率过高（已知 100 Hz）造成 MPC 积压；相邻任务之间没有留出排空时间。

**判断命令**

```bash
rostopic hz /目标轨迹topic
pgrep -af humanoid_controller
```

**解决方案**：已知 100 Hz 高频下发可能造成 MPC 积压。将上层频率降至 30 Hz，并在多个独立示例间留约 2 秒排空时间；同时检查实际执行时长、控制器 CPU 和错误日志。

**成功标准**：连续多次调用同一动作，单次执行时长不随调用次数增长。

**日志位置**：`~/.ros/log/latest/`，以及控制器终端保存的完整输出。

---

## 3. 问题：离线轨迹不随 `desire_time` 变化

**原因**：底层控制器对轨迹做了时间修剪，实际执行时间被改写，`desire_time` 不生效。

**解决方案**：确认下位机运控（`kuavo-ros-opensource`）版本与 `scripts/kuavo_humanoid_sdk_tools/sdk_version.env` 中的配套 tag 一致；反馈问题时提供轨迹时间戳、`desire_time`、运控版本或 commit、实际执行时长和第一条警告。不要通过反复发送轨迹掩盖底层时间修剪问题。

**成功标准**：在同一控制器版本下，改变 `desire_time` 能观察到实际执行时长的对应变化。

**上报信息**：见 [07 开闭源与文档](07-开闭源与文档.md) 的反馈模板。

## 4. 问题：真机运行中关节突然失能，或日志出现保护触发

**原因**：下位机运控对关节有峰值扭矩、堵转扭矩和速度保护。某个关节在设定时间窗口内持续超过阈值时，控制器会触发保护。部分电机的保护动作是**失能 / 零力矩**，高速运动中触发时，手臂可能因失去力矩而下落或继续惯性运动。

**判断方法**：在控制器终端或 `~/.ros/log/latest/` 中搜索以下关键字：

```text
Trigger peak protection
set motor <编号> disable
motor status map
[orig] tau <编号> value <原值> -> [max] <截断值>
```

保护相关字段位于运控仓库的机型配置 `src/kuavo_assets/config/kuavo_v<ROBOT_VERSION>/kuavo.json`：

| 字段 | 含义 |
|---|---|
| `peak_protection` | 峰值扭矩连续超限的时间窗口（秒） |
| `locked_rotor_protection` | 堵转扭矩连续超限的时间窗口（秒） |
| `speed_protection` | 速度连续超限的时间窗口（秒） |
| `min/max_joint_position_limits` | 关节位置命令的截断边界 |
| `joint_velocity_limits`、`joint_peak_velocity_limits` | 常规 / 峰值速度限制 |
| `joint_torque_limits`、`joint_peak_torque_limits` | 堵转 / 峰值扭矩保护阈值 |

运控真机启动文件 `load_kuavo_real.launch` 还提供 `joint_protect_enable`、`cmd_truncation_enable` 等开关，其默认值以所用运控版本的 launch 文件为准。实际启动时如果经由其他 launch 文件转发，用 `rosparam get` 和控制器启动日志确认最终值。

**解决方案**：

1. 立即停止当前任务，确认人员和设备安全；
2. 保存触发前后至少 10 秒的控制器日志、关节状态、命令值，有条件时保存视频；不要清除日志后直接重试；
3. 先检查上层下发的目标是否合理（目标位置是否超出关节范围、轨迹时间是否过短导致速度过高、末端负载是否超出预期）；
4. **不要通过放大阈值来消除保护**。确需调整保护参数时，按以下流程进行：
   - 备份原配置文件并记录修改前的值；
   - 确认数组索引对应的物理关节、字段单位以及持续 / 峰值的含义，不要凭数组位置猜测；
   - 先做 JSON 格式检查（`python3 -m json.tool <文件> >/dev/null`）和仿真验证；
   - 在隔离区、低速、低负载条件下实机验证，每次只改一类参数，并保留日志；
   - 未通过验证立即回滚。

**成功标准**：在原工况下重复运行不再触发保护，且未修改任何保护阈值；或参数修改已按上述流程完成验证并记录。

## 5. 问题：怎样让机器人停下来？各种停止方式有什么区别

**结论**：**物理急停是唯一可依赖的整机停止手段**，软件停止入口不能替代物理急停。真机运行前必须确认物理急停可随时触达。

常见停止入口：

| 入口 | 类型 | 作用 | 说明 |
|---|---|---|---|
| 物理急停 | 硬件开关 | 切断或控制驱动器电源 | 具体行为以所用硬件版本的产品说明为准 |
| `/stop_robot` | ROS Topic，`std_msgs/Bool` | 软件停止信号，控制器和遥控节点使用 | 软件停止，不等于物理急停 |
| `/cmd_vel` 持续发布零速度 | ROS Topic，`geometry_msgs/Twist` | 覆盖底盘速度命令 | 只影响底盘速度，不等于断电 |
| 遥控器上的停止按键 | 人机输入 | 部分节点会停止底盘或结束程序 | 具体按键与效果取决于遥控器型号和启动方式 |

部分启动模式下还可能有手臂轨迹规划的停止服务（如 `/bezier/stop_plan_arm_trajectory`）或 SDK 的停止服务。这些服务是否存在取决于运控的启动方式，使用前先确认：

```bash
rostopic type /stop_robot
rosservice list | grep -i stop
```

**注意**：

- 关节保护触发时的失能 / 零力矩（见第 4 条）、软件停止和零速度覆盖是三种不同的停止效果，制动距离各不相同，需要分别评估，不能互相替代；
- 仓库中**没有**经过验收的急停制动距离数据，规划真机场地和速度时需要预留足够的安全距离。

## 6. 问题：关节限位、最大速度、末端速度等安全参数在哪里查？有没有推荐值

**结论**：目前仓库**没有**经过安全评审的「推荐值 / 警告值 / 禁止值」三级安全阈值，也没有经过验收的末端最大线速度和急停制动距离。配置文件和 URDF 中的数值是控制参数或模型参数，不能直接当作安全认证值使用。

可以查阅的来源：

| 来源 | 位置（运控仓库 `kuavo-ros-opensource`） | 能否直接作为安全值 |
|---|---|---|
| 机型运行配置 | `src/kuavo_assets/config/kuavo_v<ROBOT_VERSION>/kuavo.json` | 不能。需确认单位、生效开关并实测 |
| 配置中引用的规划 / 控制模型 URDF | 以机型配置中实际引用的路径为准 | 不能等同于硬件保护阈值 |
| 整机 URDF | `src/kuavo_assets/models/biped_s<型号>/urdf/` | 只有被当前配置引用时才生效，不能混用不同型号的模型 |

**注意**：

- 同一机型可能同时存在多份 URDF（整机模型、规划 / 控制模型、显示模型），数值可能不同。以运行配置实际引用的那一份为准，不要混用；
- URDF 中关节的 `velocity` 是关节角速度，不是末端笛卡尔线速度，不能直接换算成末端速度上限；
- 订阅关节状态时，先用 `rosmsg show <类型>` 确认字段定义。`joint_q`、`joint_v`、`joint_torque` 等字段可能处于电机空间或关节空间，使用前要确认坐标系、单位和索引；
- 需要正式安全参数（例如用于项目交付或客户验收）时，联系维护者，由控制和硬件负责人在批准的工况下实测确认。
