## 1. 问题：为何某些模块只有 `.pyc`，看不到源码

**原因**：开源发行版对部分模块以 `.pyc` 制成品分发，仓库中不随附对应 `.py`。

**解决方案**：这些模块以编译后的制成品分发属于预期行为，不是下载损坏。使用时应通过公开接口调用，不要尝试反编译或替换为自行改写的版本。

**成功标准**：确认手中版本来自正式发行包，且调用走公开接口即可。

**相关**：开发者调用路径与「统一经 `adapters` 层调用」的约定见 [01-介绍](../01-介绍/)，接口签名见 [03-接口详细文档](../03-接口详细文档/)。

## 2. 问题：文档在哪，如何反馈文档问题

**解决方案**：公开文档集中在仓库 `docs/` 下，按 7 章组织：

| 章 | 内容 |
|---|---|
| `01-介绍` | 机器人基础通识、项目简介、架构与分层、术语表 |
| `02-环境安装` | 系统要求、依赖清单、安装与验证 |
| `03-接口详细文档` | core / adapters / skills / orchestration / apps / drivers / 工具层接口 |
| `04-简单案例运行` | 由简到难的运行示例 |
| `05-进阶开发指南` | 分层扩展、测试与调试 |
| `06-常见问题FAQ` | 本篇所在的常见问题分篇 |
| `07-补充内容` | 参考资料、平台适配说明 |

文档问题（描述错误、命令失效、链接断链）请随代码问题一并提交到 [GitCode Issues](https://gitcode.com/OpenLET/letools_opensource/issues)。

**成功标准**：反馈中包含出问题的篇名或路径，便于定位。

## 3. 问题：如何收集反馈所需的日志与基础信息

**判断命令**

```bash
cd ~/letools_opensource
git branch --show-current
git rev-parse HEAD
python3 --version
rosversion -d
docker --version
nvidia-smi
```

**解决方案**：反馈时只提供定位所需的版本和错误日志。发送前逐项检查并删除用户名、IP、令牌、图像、rosbag及其他客户数据；需要完整日志时由支持人员明确指定范围后再提供。

**日志位置**

| 工具 | 日志位置/命令 |
|---|---|
| catkin | `infrastructure/ros_packages/logs/<包名>/` |
| ROS/roslaunch | `~/.ros/log/latest/` |
| Docker | `docker logs --tail 300 <容器名>` |
| systemd | `journalctl -u <服务名> -n 300 --no-pager` |
| Python/LeTools | 保存完整 traceback，不要只截最后一行 |
| GPU | 保存 `nvidia-smi` 和 `docker info` 输出 |

## 4. 问题：反馈模板怎么填

**解决方案**：按下列模板填写，缺项会导致无法定位。

```text
问题所属工具：环境/catkin/SDK/ROS/Docker/MuJoCo/行为树/底盘/手臂/相机/TF
机器人型号与硬件版本：
LeTools 分支与 commit：
SDK 分支/tag：
kuavo-ros-opensource tag 与 commit：
Docker 镜像名称/摘要：
ROBOT_VERSION：
执行环境：宿主机或容器
完整运行命令：
第一个 ERROR/FATAL/Failed：
相关日志路径：
是否稳定复现：
已经执行的排查命令及结果：
支持包文件名：
```

外部用户可前往 [GitCode Issues](https://gitcode.com/OpenLET/letools_opensource/issues) 提交问题。涉及真机运动、安全参数或急停时，应停止尝试并联系维护者，不要扩大阈值或无限重试绕过故障。

**成功标准**：提交内容含「第一个真实错误」与可复现命令，且已脱敏。

> 性能类问题（MPC 积压、轨迹时间不生效）需要额外附上轨迹时间戳等信息，见 [06 性能与稳定性](06-性能与稳定性.md)。
