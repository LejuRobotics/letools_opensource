# 嘉腾底盘控制使用说明

推荐优先使用嘉腾 `/move_base` 导航接口。它提供任务 ID、到达查询和避障参数，
适合相对移动与 `map` 绝对目标。`/cmd_pose`、`/cmd_pose_world`、`/cmd_vel`
属于外部控制通道，仅用于需要直接控制时。

下列命令会产生真实运动，执行前确认现场安全，并在每次控制前确认控制模式。

## 1. 环境准备

```bash
cd ~/letools_opensource
source infrastructure/ros_packages/devel/setup.bash
```

`/enable_vel_control` 是导航与外部控制的互斥开关：

| 状态 | 可用接口 |
|---|---|
| `false` | `/move_base/base_move`、`/move_base/move_to_target` |
| `true` | `/cmd_pose`、`/cmd_pose_world`、`/cmd_vel` |

切换前确认另一类运动任务已经结束。`data=true` 时调用 `/move_base` 可能只短暂
动作后停住；服务返回 `success: true` 只表示任务已受理，并不表示到达。

## 2. 推荐：`/move_base` 导航控制

### 2.1 控制前确认导航模式

每次调用 `/move_base` 前，先关闭外部控制并读取状态：

```bash
rosservice call /enable_vel_control "data: false"
rostopic echo -n 1 /enable_vel_control_state
```

输出必须为：

```text
data: False
```

### 2.2 相对移动：`/move_base/base_move`

相对位移使用机器人当前本体坐标系：`x`、`y` 单位为米，`theta` 单位为弧度。

```bash
rosservice call /move_base/base_move "x: 0.10
y: 0.0
theta: 0.0
options: {avoid_enabled: true, avoid_distance: 0.5, linear_velocity: 0.08, angular_velocity: 0.15, position_threshold: 0.03, angle_threshold: 0.08, allow_rotation: false}"
```

响应中的 `task_id` 用于查询到达结果：

```bash
rosservice call /move_base/check_arrived "task_id: '实际返回的task_id'
blocking: true
timeout: 60.0"
```

### 2.3 绝对移动：`/move_base/move_to_target`

绝对目标使用 `/move_base/amcl_pose` 所在的 `map` 坐标系。先读取当前位姿，再选择
附近安全目标；`map` 的 x 正方向不一定是机器人正前方。

```bash
rostopic echo -n 1 /move_base/amcl_pose
```

调用示例中的目标值必须替换为现场确认过的 `map` 坐标：

```bash
rosservice call /move_base/move_to_target "x: 1.20
y: 0.40
theta: 0.0
options: {avoid_enabled: true, avoid_distance: 0.5, linear_velocity: 0.08, angular_velocity: 0.15, position_threshold: 0.03, angle_threshold: 0.08, allow_rotation: true}"
```

同样使用返回的 `task_id` 调用 `/move_base/check_arrived` 确认最终到达。

### 2.4 测试脚本

```bash
python3 apps/jiateng_adapter/test_base_move.py
python3 apps/jiateng_adapter/test_move_to_target.py
```

两个测试会在发现外部模式时打印 WARNING，并自动切换到导航模式 `false` 后执行。
每个脚本的 `main` 通过 `suite.addTest(...)` 选择实际运行的用例。

## 3. 外部控制话题

外部控制通过 Kuavo MPC/控制桥接链路驱动当前嘉腾底盘，不创建嘉腾导航 `task_id`，
也不能使用 `/move_base/check_arrived` 查询到达状态。

### 3.1 控制前确认外部模式

每次发布外部控制话题前，先开启外部控制并读取状态：

```bash
rosservice call /enable_vel_control "data: true"
rostopic echo -n 1 /enable_vel_control_state
```

输出必须为：

```text
data: True
```

确认此时没有正在执行的 `/move_base` 任务后，再发布以下话题。

| 功能 | 话题 | 类型 | 坐标系 |
|---|---|---|---|
| 相对位置 | `/cmd_pose` | `geometry_msgs/Twist` | 机器人本体坐标系 |
| 绝对位置 | `/cmd_pose_world` | `geometry_msgs/Twist` | 下位机世界坐标系 |
| 连续速度 | `/cmd_vel` | `geometry_msgs/Twist` | 机器人本体坐标系 |

### 3.2 相对位置：`/cmd_pose`

`linear.x`、`linear.y` 为相对位移（m），`angular.z` 为相对 yaw（rad）。

```bash
rostopic pub -1 /cmd_pose geometry_msgs/Twist \
'{linear: {x: 0.10, y: 0.10, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

可通过以下话题读取 MPC 预计到达时间：

```bash
rostopic echo /lb_cmd_pose_reach_time
```

### 3.3 绝对位置：`/cmd_pose_world`

`/cmd_pose_world` 使用下位机世界坐标，不能直接视为 `/move_base/amcl_pose` 的
`map` 坐标。

```bash
rostopic pub -1 /cmd_pose_world geometry_msgs/Twist \
'{linear: {x: 0.50, y: 0.20, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

### 3.4 连续速度：`/cmd_vel`

控制链路：

```text
/cmd_vel → /nodelet_manager → /move_base/base_cmd_vel
         → /leju_node → 嘉腾底盘
```

以 20 Hz 发布 `0.10 m/s` 前进速度：

```bash
rostopic pub -r 20 /cmd_vel geometry_msgs/Twist \
'{linear: {x: 0.10, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

按 `Ctrl-C` 停止连续发布后，再发送一次零速度：

```bash
rostopic pub -1 /cmd_vel geometry_msgs/Twist \
'{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

## 4. 控制模式切换脚本

```bash
python3 apps/jiateng_adapter/test_enable_vel_control.py
```

该脚本提供以下显式操作，并保留切换后的模式：

```text
test_01_get_current_state  读取当前模式
test_02_set_false          切换到嘉腾导航模式
test_03_set_true           切换到外部控制模式
```
